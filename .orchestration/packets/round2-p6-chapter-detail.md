目标：重做韩国语课程巩固的"章节巩固详情"页面，让每一章展示自己的真实内容，不再是所有章节
共用同一套硬编码가/고/한/읽字母互动。这是第二轮第一个任务。

背景文档：docs/korean-practice-center-integration-roadmap.md 第4.2、8.3、8.4节（先读文档，不要
复述给我，直接按其中定义实现）。

已完成的前置依赖（第一轮成果，直接复用，不要重新设计）：
- 数据表 `chapter_practice_units` / `chapter_practice_blocks`
  （`supabase/migrations/202608190015_chapter_practice_content.sql`）。
- 学生端目录已读取真实课程树并按章节关联 `chapter_practice_units`：
  `src/lib/course-practice-catalog.server.ts`、
  `src/app/[space]/apps/korean/practice/course/`。
- 管理端已可为章节生成、编辑、发布 `chapter_practice_blocks`，block_type 和 content_payload 的
  实际数据形态见 `src/features/chapter-practice/api/management-service.ts` 和
  `src/features/chapter-practice/api/model.ts`（本任务只读取消费这些已发布数据，不要改写生成
  逻辑或数据形态；如果发现详情页需要的数据 content_payload 里没有，先去看能不能通过调整消费方式
  解决，只有确实无法满足才可以在报告中提出最小化调整建议，不要擅自改表结构）。
- 原有韩文字母拼装/拆解/纠错/分类互动组件（自己在项目里找现有实现，通常在课程巩固章节详情
  相关目录下）。

已冻结的决策：
- 章节巩固详情页改为读取该章节已发布版本的 `chapter_practice_units` 及其
  `chapter_practice_blocks`，按 8.3 顺序渲染：本章回顾 → 核心词汇 → 核心语法 → 易混对比 →
  听说读写综合练习 → 本章错题 → 自我检测 → 巩固结果。**监听训练(listening)的真实数据接入不在
  本任务范围**，本任务对 listening 类型的块只需要能正常渲染已有的 content_payload（哪怕内容简单），
  不需要做播放器、正确率统计等；那是下一个任务的范围。
- 不是每一章都要机械显示全部八种内容块；只渲染该章节实际发布的、enabled 的内容块，缺失的块
  不显示（不留占位空白，也不报错）。
- 原有韩文字母拼装/拆解/纠错/分类互动组件保留，但只应用于"字母/发音"类章节（自己判断依据，
  例如章节所属课程是 `hangul-introduction` 或章节的 block content_payload 明确标记为字母练习
  来源；具体判断策略你决定，但要在报告中说明依据）。其他章节（韩国语一级第1—16章及其他课程）
  一律读取自己发布的 `chapter_practice_blocks` 内容，不得再复用同一组가、고、한、읽案例。
- 自我检测和巩固结果页：学生作答后要有明确反馈（对/错、解释或评分说明）和明确的下一步操作
  （重新练习/进入下一模块/返回目录等），不能只是提交后无声跳转或停在原地不给指引。
- 精确掌握度计算、跨设备进度持久化仍是第三轮"统一进度"范围，本任务不需要实现，可以先用现有
  的临时判断（比如页面内 state 或已有的本地判断方式）过渡，只要不再依赖硬编码的字母互动作为
  唯一判断依据即可。
- 遵守项目文案规范（AGENTS.md）：不要引入装饰性英文栏目标签/eyebrow/typeLabel；卡片标题+
  补充说明复用 `@/components/ui/card-title-with-hint`；状态同时用文字和图标。

不要做的事（non-goals）：
- 不实现听音训练真实数据接入（下一个任务）。
- 不实现统一进度数据库写入（第三轮）。
- 不修改管理端生成/编辑/发布逻辑和数据表结构。
- 不修改课程巩固目录页（第一轮已完成，只改详情页）。

验收标准：
- 用至少两个不同章节（一个字母/发音类章节 + 一个韩国语一级正式章节）验证页面显示的内容确实
  不同，且都来自各自真实发布的巩固内容，而非同一套字母案例（用真实数据/真实渲染结果验证，
  不能只做静态代码审查）。
- 非字母类章节完全不出现硬编码的가/고/한/읽案例内容。
- 学生完成自我检测后能看到明确反馈和下一步操作，用真实交互流程验证。
- 类型检查/构建/相关自动化测试通过。
