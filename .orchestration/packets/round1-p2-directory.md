目标：学生端"课程巩固"目录（`/[space]/apps/korean/practice/course`）改为读取真实课程结构，
不再依赖旧的 `chapter_tests` 拼出目录，也不再把课程范围写死为
`hangul-introduction` / `korean-level-one` 两个键。

背景文档：docs/korean-practice-center-integration-roadmap.md 第4.1、8.1、8.2节（先读文档，
不要复述给我，直接按其中的定义实现）。

已冻结的决策：
- 目录数据来源改为 `courses → lessons → course_chapters`，覆盖当前机构已开通韩语应用下的全部
  已发布课程，不限于原来两个课程键。
- 必须遵守：课程/课时/章节发布状态、课程开放时间、管理端手动锁定、前置章节完成关系
  （这些控制字段已经在管理端课程管理中存在，自己去现有管理端课程相关代码/表里找字段名，
  不要新增字段）。
- 每章巩固状态判断新增一种情况：若该章节暂无"已发布"的 `chapter_practice_units`（本轮 P1 刚建的
  表，见 `supabase/migrations/202608190015_chapter_practice_content.sql`），状态显示"内容准备中"，
  不要报错、不要显示空白。已发布 practice unit 存在但学生尚未开始/进行中/已达标，按文档 8.2 的
  状态集合（未开始/巩固中/待加强/已掌握/未开放/内容准备中）呈现，但本轮不要求做出精确的
  掌握度计算逻辑——那是第三轮"统一进度"的范围；本轮只要能正确区分"未开放"（课程/章节未发布或
  未到开放时间或被锁定或前置未完成）与"内容准备中"（已开放但无已发布巩固内容）与"可进入"
  （已开放且有已发布巩固内容）三种即可，具体到"已掌握/待加强"等更细状态可以先复用现有旧进度
  数据或留空，不阻塞本任务验收。
- 章节测试（`chapter_tests`）本轮不再作为目录来源，但保留其数据和作答记录不动，仍可作为其他
  功能的数据来源（本任务不需要碰它）。

不要做的事（non-goals）：
- 不要重做章节巩固详情页内部内容（韩文字母精研工作台等），那是第二轮范围。
- 不要实现巩固包自动生成逻辑（管理端生成草稿是 P4 的任务），本任务只读取已存在的
  `chapter_practice_units`（如果为空，全部按"内容准备中"处理，这是预期的中间态，不是 bug）。
- 不要修改 `chapter_practice_units` / `chapter_practice_blocks` 表结构或 RLS。
- 不要修改精研进度的 localStorage 逻辑（第三轮范围）。
- 遵守项目 CLAUDE.md/AGENTS.md 的文案规范：不要引入装饰性英文栏目标签、eyebrow、
  typeLabel 等；卡片标题+补充说明要复用 `@/components/ui/card-title-with-hint`（如果本任务改动
  涉及这类卡片）。

验收标准：
- 目录不再包含任何对 `hangul-introduction` / `korean-level-one` 字符串键的硬编码限制（用 grep
  自查确认，并在报告中给出命令与结果）。
- 新增一门测试用已发布课程（或使用现有数据库中已发布的课程数据，不限于原两门）后，能出现在
  学生端目录中；未发布、未到开放时间、被锁定的课程/章节不出现或明确显示为不可进入。
- 页面本地类型检查/构建（找项目里现成的 typecheck 或 build 脚本）通过。
- 若项目有相关的现有自动化测试（单测/集成测试），需要跑一遍确认未破坏；如果没有覆盖此页面的
  自动化测试，需在报告中说明并至少完成一次真实的手动/脚本化功能验证（例如用测试账号跑一次
  页面渲染或 API 调用，不能只做静态代码审查）。
