# Packet: Round1/Packet2c — 诊断本地迁移链在202608190004处失败

## 背景
`npx supabase db push --local` 从干净状态推进时，在
`supabase/migrations/202608190004_fix_listening_backfill_trigger_order.sql`
处失败，报错含义大致为"某章节缺少可用的真实听力活动"。这阻断了后续对
`202608190023`/`202608190024`（本方案期中卷草稿迁移）做真实全链路数据库验证。

## 目标
只做诊断与"数据修复"，不改写任何历史迁移文件内容：
1. 确认该失败的根因：是某个前置迁移/种子步骤本应写入某章节的听力活动数据但未写入
   （数据缺口），还是 004 号迁移本身逻辑有缺陷。
2. 如果是数据缺口：找到应当提供该数据的既有迁移或种子来源（如果该章节的听力活动数据
   本应由更早的迁移写入却因为某种原因缺失或顺序问题未生效），评估是否可以通过新增一个
   之后的迁移（不修改004号及更早文件本身）来补齐缺失数据，使 `npx supabase db push --local`
   从干净状态可以完整跑通到最新迁移（含023/024）。
3. 如果确认必须修改历史迁移文件本身才能修复，**不要修改**，如实在报告中说明具体原因、
   影响范围和你认为可行的两种以上方案，交由人工决策，不要自行调整历史文件。

## 非目标
- 不修改 004 号或更早的任何历史迁移文件。
- 不修改期中卷内容合同、023/024迁移的题目内容。
- 不引入正式音频文件；如需要占位数据，必须标记为 `temporary`，不得标记 `formal`。

1. 报告明确指出根因（数据缺口 vs 迁移逻辑缺陷）及具体涉及哪个章节/哪张表。
