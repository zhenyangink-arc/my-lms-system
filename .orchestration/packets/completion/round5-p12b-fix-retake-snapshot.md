# Packet: Round5/Packet12b — 修复补考卷快照错配 + 补完浏览器验证

## 背景
Round5/Packet12 报告了一个真实缺陷：当机构为学生选择与原始考试不同的补考卷时，
学生答题界面仍然读取的是原始assignment的题目快照，而不是新选定补考卷的题目。
另有两项验收（深链可达性、老师补考浏览器投递）因缺少真实登录浏览器端到端验证
而被判定BLOCKED，不是代码问题，需要补测。

涉及文件线索（来自Packet12报告，自行核实）：
`src/features/student-home-learning/api/assignment-exam-mapper.ts`、
`assignment-exam-source.ts`、`src/lib/assignment-detail-data.ts`、
`src/app/dashboard/assignments/[assignmentId]/page-content.tsx`、
`src/app/dashboard/assignments/actions.ts`。

## 目标
1. 修复补考卷题目快照错配：学生打开补考任务时，题目、答案、材料必须来自机构实际
   选定的补考母卷，而不是原始考试的快照。
2. 用真实登录浏览器（不是伪造session/静态断言）完整走一遍：
   - 老师从资格明细发起补考投递（选择与原考试不同的合法补考母卷）。
   - 学生登录后打开补考任务，确认题目确实来自新选定的补考卷。
   - 学生完成提交，老师批改，成绩发布，资格重新计算。
3. 用真实登录浏览器逐一点击至少5类缺口深链（教材、作业、章节巩固、专项训练、
   错题复习），确认均返回200且到达可操作页面，不是404或占位页。

## 非目标
- 不改变补考投递机制本身的产品设计（选卷、名单、时间、取分策略字段不变）。
- 不修改资格计算算法核心逻辑（Packet7已验证正确）。

## 验收标准
1. 补考卷切换后，学生看到的题目/答案/材料与新选定母卷一致（有真实查询/页面截图证据，
   覆盖题目ID层面的比对，不能只看题目数量）。
2. 真实浏览器完整走通：投递（换卷）→学生作答→批改→发布→资格刷新，全部为真实操作
   非静态断言，附截图或录制记录。
3. 至少5类深链在真实登录浏览器中逐一验证为200且到达可操作页面。
4. 既有测试、typecheck、lint通过；`git status`范围可控；测试数据清理。

## 交付形式（报告）
- 缺陷根因与修复说明。
- 每条验收标准 PASS/FAIL/BLOCKED，附真实证据。
- 验证命令、退出码。
- 已知风险（含之前提到的"远端环境尚未部署本次migration"是否需要处理）。
