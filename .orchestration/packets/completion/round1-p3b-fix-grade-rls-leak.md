# Packet: Round1/Packet3b — 修复成绩未发布前的RLS数据泄露（安全修复，非本方案范围创建，属既有缺陷）

## 背景
Round1/Packet3 端到端验证发现：老师完成人工批改但**尚未发布成绩**时，学生仍可通过直接
数据库/REST查询读取到主观题评分、量规分项和老师评语等内部字段，即使前端UI已经做了
"发布前不展示"的最小化处理。这是提交/批改相关表现有RLS策略的缺陷，不是本方案新增功能
引入的问题，但违反了平台既有安全预期（学生只能在成绩发布后看到评分明细）。

涉及路径线索（来自Packet3报告，请自行核实并查找完整范围）：
`src/app/dashboard/assignments/[assignmentId]/page-content.tsx`，以及支撑该页面的
提交/评分数据表（学生提交、量规评分、评语相关表）。

## 目标
1. 定位所有存放主观题评分、量规分项分数、老师评语的表，找出当前允许学生角色在
   成绩未发布状态下直接读取这些字段的RLS策略或视图。
2. 修复RLS，使学生只能在对应任务成绩已发布（`grade_released`或等价状态）后，
   读取到自己提交的评分明细和评语；发布前学生只能读取到已有的客观题即时分和
   提交状态（沿用Packet3已实现的前端最小化读取范围，但这次要在数据库层面强制）。
3. 不得影响老师、机构管理员等角色按既有权限继续在批改流程中读写这些字段。
4. 新增迁移实现修复；不修改无关表或无关RLS策略。

## 非目标
- 不改变成绩发布本身的业务流程或状态机。
- 不影响客观题即时分的现有可见性（这部分Packet3验证为正确，保持不变）。
- 不涉及本方案期中卷特有的表（除非评分表本身就是共享表）。

## 验收标准
1. 用真实测试学生账号，在成绩发布前直接查询数据库/REST，无法读取到主观题评分、
   量规分项、老师评语字段（返回空或被拒绝，不是前端过滤）。
2. 成绩发布后，同一学生账号可以正常读取到完整评分明细，与现有功能一致。
3. 老师/机构管理员在批改阶段的读写权限不受影响，用真实账号验证。
4. 复用或扩展 Round1/Packet3 报告中提到的 `tests/assignment-rubric-grading.test.mjs`
   或新增测试，覆盖"发布前学生直接查询被拒绝/为空"这一断言，防止回归。
5. 既有全量测试、typecheck、lint 通过。
6. `git status` 范围可控，测试完成后清理临时测试账号和数据。

- 验证命令、退出码。
- 风险说明：是否有其他既有功能依赖了原先的（有漏洞的）宽松策略。
