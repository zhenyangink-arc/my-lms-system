# Packet: Round1/Packet3 — 期中考试发布与真实投递

## 背景
方案文档：`docs/korean-level-one-midterm-final-certification-roadmap.md` 第22节 Round1/Packet3。
`EX-K1-MID-V1` 草稿（35题、四选项、及格分60、`allow_resubmission=false`）已通过质检
（0项缺口），当前仍是 draft、对学生/机构不可见。迁移：023、024。

## 目标
1. 通过仓库现有的平台发布流程/按钮（管理端已有的试卷发布能力，不新建发布机制）将
   `EX-K1-MID-V1` 发布为可被机构使用的正式母卷。
2. 验证机构老师能通过现有 `learning_assignments` 投递流程选择该母卷并布置给班级/学生
   （开始/截止时间、最大提交次数、成绩公开时间等沿用现有机制，不新增字段）。
3. 验证学生端能看到正确的任务时间、剩余次数和状态。
4. 验证学生提交后：客观题（V/G/L/R）自动判分；主观题（S/W）进入人工批改队列；
   老师批改并发布成绩后，学生能看到成绩、评分明细和反馈；该任务进入现有"今日学习"聚合。

## 范围与非目标
- 全程复用现有发布、投递、提交、判分、批改、成绩发布链路，不新建新的考试系统或页面。
- 不创建结课政策、资格计算或证书相关任何内容（Round3/4范围）。
- 不修改学生首页/今日学习的既有架构，只验证期中卷任务能正确出现。

## 验收标准
1. 发布后 `EX-K1-MID-V1` 状态变为已发布，且已发布版本内容被锁定（不可再直接编辑）。
2. 真实创建一条投递记录，机构可见、学生可见，时间/次数/状态字段与投递配置一致。
3. 用真实测试账号模拟学生完整提交一次（含至少1个口语音频占位与1个写作长文本），
   客观题自动判分结果正确；主观题进入待批改，不能被误判为"提交失败"。
4. 用真实测试老师账号完成口语、写作分项量规批改并发布成绩；学生端能看到发布后的成绩
   与老师反馈；成绩未发布前学生不可见内部评分。
5. 该任务出现在学生"今日学习"聚合中，且状态随生命周期正确流转（待完成→待批改→已发布）。
6. 全部验证使用真实数据库操作和真实查询结果，不是静态代码走读；测试完成后清理测试账号
   和测试投递/提交数据，不污染仓库种子数据。
7. `git status` 范围可控；既有测试、typecheck、lint 通过。

## 交付形式（报告）
- 改动文件列表（如有代码改动；若纯粹是数据操作验证，说明未改代码）。
- 每条验收标准 PASS/FAIL/BLOCKED。
- 验证命令、真实查询结果、退出码。
- 已知风险、假设、范围偏差。
