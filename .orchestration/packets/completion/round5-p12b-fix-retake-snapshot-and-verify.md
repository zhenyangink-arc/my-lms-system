# Packet: Round5/Packet12b — 修复补考卷题目快照错配 + 补齐浏览器验证

## 背景
Round5/Packet12 报告了一个真实功能缺陷：老师为学生指定与原考试不同的补考母卷时，
学生打开补考任务，答题界面读取的仍是原始assignment的题目快照，而不是补考母卷的
题目。这会导致学生看到错误的题目/选项。另外还有两条验收标准未经真实浏览器验证：
1. 5类缺口深链是否真实可达（非404）。
2. 老师完整走一遍补考投递浏览器流程、学生打开补考任务提交、发布成绩、验证效果。

涉及文件线索（来自Packet12报告，请自行核实完整范围）：
`src/app/dashboard/assignments/[assignmentId]/page-content.tsx`、
`src/lib/assignment-detail-data.ts`、`src/app/dashboard/assignments/actions.ts`、
补考RPC相关的 `learning_assignments`/`learning_assignment_retake_students`。

## 目标
1. 定位并修复题目快照错配的根因：补考任务的题目来源必须与该次补考实际指定的母卷
   一致，不能沿用原始assignment的题目快照。
2. 用真实数据验证：老师给同一学生分别指定"与原卷相同"和"与原卷不同"两种补考母卷，
   两种情况下学生打开任务看到的题目、选项、答案判定都必须与各自母卷一致。
3. 补齐浏览器端到端验证（用真实登录账号，不是静态代码走读）：
   - 老师登录，从学生资格明细发起一次补考投递（选择与原卷不同的母卷）。
   - 学生登录，打开该补考任务，确认看到的是补考母卷的题目，完整作答提交。
   - 老师批改主观题并发布成绩。
   - 验证学生资格按补考成绩正确重新计算。
   - 依次点击至少5类缺口的"去完成"深链（教材、作业、章节巩固、专项训练、错题复习），
     确认均到达真实可用页面，不是404或占位页。

## 非目标
- 不改变补考的选卷/取分策略业务规则本身，只修复"读取哪份题目快照"的错配。
- 不新建补考系统。

## 验收标准
1. 补考题目快照与实际指定的补考母卷一致（不同卷场景下用真实数据验证选项/答案不再
   与原卷混淆）。
2. 浏览器端到端流程（投递补考→学生作答→批改发布→资格重算）全部用真实账号完成，
   附操作记录/截图。
3. 5类缺口深链逐一验证真实可达。
4. 既有测试、typecheck、lint通过；新增/修改回归测试覆盖"补考读取正确题目快照"这一断言。
5. `git status`范围可控（本Packet自身改动可辨识），测试数据清理。

## 交付形式（报告）
- 根因说明与修复文件列表。
- 每条验收标准 PASS/FAIL/BLOCKED，附真实证据。
- 验证命令、退出码。
