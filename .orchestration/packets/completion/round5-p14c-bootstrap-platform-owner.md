# Packet: Round5/Packet14c — 新增引导性平台负责人迁移（打通空库重放）

## 背景
Packet14b已诊断清楚：`202608190007`及后续多个迁移（008、014、023、200002）都要求
存在一个有效的平台负责人（`global_role='platform_owner'`且状态有效），但仓库中
从未有任何迁移负责创建这个初始账号，导致全新空库`db reset --local`必然在007处失败。
已有正常部署环境不受影响（它们已经有真实负责人）。

已批准方案：新增一个时间戳位于`202608190006`与`202608190007`之间的全新迁移
（例如`202608190006005000`这类可排序在两者之间的写法，具体由你决定，只要保证
`006 < 新迁移 < 007`的字典序排序），条件式创建一个不可登录的引导用平台负责人
审计主体（不是真实可登录账号，无生产密码，无identity），仅在完全没有任何平台
负责人时才创建；已有负责人的环境不受影响、不产生重复账号。

## 目标
1. 新增该迁移：先查找是否已存在满足007/008/014/023/200002各自查找条件的平台负责人；
   全部为空时，创建对应的`auth.users`记录（无可登录identity/密码）和`profiles`记录
   （`role='platform_super_admin'`、`global_role='platform_owner'`、`status='active'`，
   以及007/008/014/023/200002实际检查的其他必要字段，需逐一核实这些迁移的查找条件
   并全部满足）。
2. 幂等：重复执行不产生重复账号或报错。
3. 验证：从空库执行`npx supabase db reset --local`完整跑通全部迁移，包括
   `202608200001`—`202608200008`，退出码0，迁移账本正确登记全部版本号。
4. 验证：在一个已有真实平台负责人的数据库状态下重放，该迁移不产生新账号、不影响
   现有负责人。
5. 用真实数据库验证007/008/014/023/200002在这个新迁移之后都能正常创建各自的试卷，
   `created_by`/`updated_by`正确指向某个有效负责人。

## 非目标
- 不修改007、008、014、023、200002或其他任何既有历史迁移文件。
- 不在正式管理界面开放"创建第二个平台负责人"的入口（该限制维持不变）。
- 不处理已部署远端环境的`db push --include-all`执行本身（那是部署操作，写在报告的
  部署建议里即可，不在本Packet执行）。

## 验收标准
1. 新迁移文件时间戳正确落在006和007之间，`git diff`确认007及以后历史文件未被修改。
2. `npx supabase db reset --local`从空库退出码0，`202608200001`—`202608200008`
   全部在迁移账本中登记。
3. 已有负责人场景重放验证不产生重复/冲突账号。
4. 007/008/014/023/200002在此迁移之后成功创建各自试卷，`created_by`有效。
5. Round1—Round5此前各Packet的真实数据库验收脚本（至少
   `scripts/verify-course-completion-evaluator.mjs`、
   `scripts/verify-course-completion-certificates.mjs`）在新的干净数据库上
   重新跑一遍确认仍然通过。
6. 既有测试、typecheck、lint通过；`git status`范围仅限新迁移文件。

## 交付形式（报告）
- 新迁移文件路径、核心实现说明。
- 每条验收标准 PASS/FAIL/BLOCKED，附真实证据。
- 验证命令、退出码。
- 对已部署远端执行`db push --include-all`的具体操作建议（写在报告里，不要代替
  用户执行）。
