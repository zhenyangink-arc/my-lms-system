# Packet: Round1/Packet2d — 修复历史迁移004的发布状态筛选（用户已决策）

## 背景

在遍历第1—16章寻找"真实听力活动"时，额外要求 `chapter/version/textbook.status = 'published'`。
但当前16章教材全部为 `draft`（编辑/母语/音频/图片审核未完成，尚未走平台负责人发布RPC），
导致该条件恒为假，从干净状态跑 `supabase db push/reset --local` 必定在004处失败，
阻断包括本方案023/024（期中卷草稿）在内的所有后续迁移。

用户已明确决策（不需要再询问）：**放宽004的筛选条件，允许草稿状态教材章节的听力活动
作为作业听力回填来源**，恢复到004之前（001）的语义。理由：草稿阶段内容和正式发布后
在“是否存在可用听力活动”这个判断上应是等价的，只是提前生效；这个改动小、风险低。

## 目标
1. 新增一份时间戳晚于最新已有迁移的迁移文件，修正004引入的 `published` 限制
   （移除或放宽该状态过滤条件，恢复到更早版本允许draft章节参与的语义）。
   **不要直接编辑或删除004文件本身**——004已被部署，历史迁移文件不可篡改；
   用新迁移覆盖/修正其触发器或函数定义。
2. 修复后，从干净状态执行 `npx supabase db reset --local`（或等效的 `db push --local`
   从空库开始）必须完整跑通全部迁移，包括023、024，退出码0。
3. 修复后重新验证 Round1/Packet2b 中未能验证的两个断言，并给出真实查询证据：
   - 期中卷质检从"3项缺口"变为"0项缺口"。
   - 非管理会话查询不到 `EX-K1-MID-V1` 母卷和题目（RLS不可见性）。
4. 确认这个筛选放宽不会破坏现有依赖"仅published才回填"这一行为的其他功能——如果
   仓库中有测试或代码假设了该限制，需要一并确认是否仍然合理，并在报告中说明。
