# Packet: Round4/Packet11 — 学生结课页面

## 背景
方案文档第15.4、16、22节。机构审核端已可颁发/撤销/重新颁发证书（Packet10）。
本Packet做学生端只读页面。

界面文案规范（CLAUDE.md硬性要求）：不生成装饰性英文眉题/类型标签；标题补充说明复用
`@/components/ui/card-title-with-hint`；学习卡片默认只显示简洁标题，场景/背景/操作说明
放在标题右侧圆形叹号提示图标中。

## 目标
在现有成绩范围内新增页面 `/{space}/apps/korean/grades/completion`（路由前缀以仓库
现有成绩模块实际路径为准，如与文档路径不同，遵循仓库既有约定并在报告中说明），展示：
1. 首屏结论：未满足/等待批改/符合资格/已颁发（方案16"首屏先显示结论"）。
2. 已完成要求、未完成要求（自然语言原因+真实深链"去完成"）。
3. 等待批改状态（不要求学生重复提交）。
4. 期中`EX-K1-MID-V1`、期末`EX-K1-FIN-V1`成绩。
5. 已颁发证书展示（姓名、课程、颁发机构、日期清晰可读）；撤销/重新颁发状态展示。
6. 打印布局（方案16"证书打印布局与屏幕布局分离"）。

学生只能读取自己的数据（复用已有RLS，不新增放宽策略）。

## 非目标
- 不做机构/老师端任何页面（已完成或非本Packet范围）。
- 不修改资格计算、证书RPC或RLS。
- 不是新的学生首页或新的一级导航，是成绩范围内的二级详情页。

## 验收标准
1. 学生只能看到自己的资格与证书；用真实账号验证跨学生不可见。
2. 未达标学生看到最重要的下一步，不堆叠所有入口；每个要求同时有文字和图标状态。
3. 已颁发证书信息清晰完整；打印布局与屏幕布局分离（有独立的打印样式/视图）。
4. 375px视口无横向滚动；触控区域≥44px；标题说明复用`card-title-with-hint`；
   无装饰性英文眉题。
5. 用真实浏览器走一遍：未达标学生视图→等待批改学生视图→已颁发证书学生视图→打印预览，
   附截图证据。
6. 既有测试、typecheck、lint通过；`git status`范围可控。

## 交付形式（报告）
- 新增/修改页面文件列表。
- 每条验收标准 PASS/FAIL/BLOCKED，附证据（含浏览器验证截图）。
- 验证命令、退出码。
- 已知风险、UI取舍说明。
