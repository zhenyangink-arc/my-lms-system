# Packet: Round4/Packet9 — 证书与审计表

## 背景
方案文档第13、14、18.3、22节。资格计算体系已就绪：`student_course_completion_evaluations`
的`eligible`状态由service_role RPC计算（Packet7/8）。本Packet建立证书本体。

## 目标
1. 新增`course_completion_certificates`（方案13.1字段）：
   - `certificate_number`：服务端生成、全局唯一、不可预测、不暴露学号/邮箱/主键、
     不允许客户端自定义、姓名变更不改变编号。生成函数需说明其不可预测性来源
     （如加密安全随机而非简单序列）。
   - `status`：`issued/revoked/reissued`。
   - 保存政策快照、证据快照、综合成绩快照、姓名/课程名称快照（方案19"证书保存颁发时
     快照，不随后续变化改写"）。
2. 新增`course_completion_certificate_events`（方案13.3）：只追加、不更新历史事件；
   事件类型至少含`issued/revoked/reissued`（`downloaded/verification_viewed`可选，
   若本Packet不实现下载/查验功能可以先建表结构占位但不强制写入）。
3. 颁发/撤销/重新颁发RPC（方案5.2、14）：
   - 只有对应机构负责人可颁发本机构证书，且只能对`eligible`状态的资格记录颁发；
     不符合资格不能颁发（数据库层强制，不只是应用层判断）。
   - 撤销必须提供原因，不删除原证书，只改状态+追加事件。
   - 重新颁发生成新证书编号，新证书关联原证书（`reissued_from_id`），旧证书仍可查询
     但显示已撤销/已被替代。
   - 双击颁发（并发颁发同一资格）只产生一张有效证书（方案25.4并发要求）。
4. RLS（方案18.3、18.4）：机构只能操作本机构；平台负责人可查看全局并在异常情况撤销；
   学生只能读自己的证书；不能任何角色直接写证书表（必须走RPC）。

## 非目标
- 不做机构审核UI、学生证书页面（Packet10/11）。
- 不做公开查验RPC（方案18.5，后续可选功能，本Packet不实现）。
- 不修改资格计算算法本身。

## 验收标准
1. 用真实`eligible`资格记录，机构负责人成功颁发；证书编号全局唯一、格式不可预测
   （抽样生成多个编号，验证无简单递增/可猜测规律）。
2. 对`not_eligible`或`pending_grading`状态的资格记录尝试颁发被数据库拒绝。
3. 并发测试：对同一资格记录同时发起两次颁发请求，只产生一张状态为`issued`的有效证书。
4. 撤销：提供原因后状态变为`revoked`，原记录未被删除，审计事件表追加一条`revoked`事件。
5. 重新颁发：生成新编号，新记录`reissued_from_id`指向原证书，原证书状态可查询为
   已被替代/撤销。
6. RLS验证：机构A无法颁发/撤销/查看机构B证书；老师无法颁发或撤销证书；学生只能读自己的
   证书，无法直接INSERT/UPDATE证书表。
7. 既有测试、typecheck、lint通过；`git status`范围可控；测试数据清理。

## 交付形式（报告）
- 新迁移文件、表结构与RPC签名摘要。
- 每条验收标准 PASS/FAIL/BLOCKED，附真实证据（含证书编号样本、并发测试结果）。
- 验证命令、退出码。
- 证书编号生成算法说明。
