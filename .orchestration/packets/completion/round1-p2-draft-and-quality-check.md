# Packet: Round1/Packet2 — 期中考试草稿与质量检查

## 背景
方案文档：`docs/korean-level-one-midterm-final-certification-roadmap.md`（第6、8、22节）。
上一 Packet 已冻结内容合同：`docs/exams/korean-level-one-midterm-v1-content-contract.md`，
含全部35道候选题（V/G/L/S/R/W）、答案、解析要点、听力/阅读材料原文、口语与写作量规。

仓库已有第1—16章正式章节考试草稿与4套阶段考试草稿，是本 Packet 录入期中卷草稿时
应遵循的既有数据结构与录入方式，请先探索并复用其模式，不要发明新存储方式。

## 目标
1. 依据内容合同，将 `EX-K1-MID-V1` 写入母卷草稿（`assessment_papers` /
   `assessment_paper_questions` 或仓库实际使用的等价表），草稿状态必须是不对学生/机构可见的
   draft 态，与现有章节考试草稿的可见性规则一致。
2. 写入全部题目、客观题答案与解析、主观题（口语S01、写作W01）量规快照、听力/阅读材料快照、
   听力音频状态标注（`temporary`，非 `formal`）。
3. 扩展现有发布质量检查逻辑，使其能识别期中卷并执行方案第8节列出的检查项（母卷代码规则、
   总分=100、六项能力齐全且分值符合配置、章节覆盖数量、客观题有答案解析、主观题标记人工批改、
   量规总分与题目分值一致、听力音频状态校验、无重复题干/选项、题目数量与快照一致）。
4. 管理端质检结果展示改为逐条列出未通过项，不得只显示笼统的“配置尚未完成”。

## 范围与非目标
- 允许：新增数据库迁移文件（遵循仓库现有迁移规范和命名），新增/修改质检逻辑代码，
  新增/修改管理端质检结果展示的必要部分。
- 不允许：接入真正的发布按钮或机构布置流程（这是 Round1/Packet3 的范围）。
- 不允许：新建结课政策、资格计算、证书相关任何表或代码（Round3/Round4范围）。
- 不允许：修改学生端页面或现有提交、判分状态机。
- 草稿此时仍必须保持不可发布（即质检未必全部通过也可以，只要草稿本身处于 draft 且不可见）。

## 冻结决策
- 母卷代码固定为 `EX-K1-MID-V1`，后续修改不得覆盖，只能复制为 V2。
- 内容严格来自 `docs/exams/korean-level-one-midterm-v1-content-contract.md`，不得自行改写题目、
  答案或量规数值；如发现合同本身有内部矛盾，先在报告中指出并按合同原文取值，不要自行"修正"。

## 验收标准
1. 草稿在数据库中存在，`paper_code`（或等价字段）为 `EX-K1-MID-V1`，状态为 draft，
   对学生和机构查询不可见（用真实查询或已有的可见性测试路径验证，不是靠前端隐藏）。
2. 全部35道题目、答案、解析、材料快照、量规快照与内容合同一致；总分字段计算结果为100。
3. 质检逻辑对期中卷生效，且能针对本 Packet 故意制造的至少1个已知缺陷（例如临时把某题分值
   改错后运行质检）返回明确指向该缺陷的逐条错误信息，而不是笼统失败；验证后必须撤销这个
   临时缺陷，恢复为合同一致的正确数据。
4. 客观题（V/G/L/R）可被现有自动判分逻辑判定；主观题（S/W）标记为需要人工批改。
5. `git status` 范围可控：只涉及迁移、质检逻辑、管理端质检展示相关文件，无关文件未被修改。
6. 运行仓库现有类型检查/lint/相关测试，全部通过；如仓库有针对试卷发布质检的既有测试套件，
   需运行并通过，或新增覆盖本次扩展逻辑的测试。

## 交付形式（报告）
- 改动文件列表（迁移、代码、测试）。
- 每条验收标准 PASS/FAIL/BLOCKED。
- 实际执行的验证命令、退出码与关键输出（含第3条"故意缺陷→恢复"过程的证据）。
- 已知风险、假设、范围偏差。
