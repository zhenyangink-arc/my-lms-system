# Study-abroad deep pages

- Route: `/[space]/apps/study-abroad/universities/comparison`, `/[space]/apps/study-abroad/universities/library`, `/[space]/apps/study-abroad/universities/library/[universityId]`, `/[space]/apps/study-abroad/universities/targets`
- Audience: Student
- Archetype: Comparison workspace (university comparison); Collection (university library); Detail (university detail); Collection / Form (target universities)
- Primary job: Let students compare shortlisted universities, browse the published university collection, inspect one university’s planning details, and maintain an actionable target-school list without leaving the study-abroad workspace.
- Primary action: Comparison — return to the library to fill comparison slots; Collection — open a relevant university or move to targets/comparison; Detail — review the school introduction and available programs; Form — add a target university, then maintain each target’s application status.
- Information hierarchy: Student shell H1 → route/page H2 → page-content H3 sections → H4 item titles where nested. Comparison uses navigation/actions → slot summary → structured comparison → guided empty state. Collection uses navigation → collection summary → browser/results → empty or error state. Detail uses back navigation → school identity → reference metrics → introduction → programs → source caution. Form uses back navigation → error state if needed → summary → add form → current targets or guided empty state.
- Layout and density: Comfortable desktop density with a fluid content width up to 1500px. Collections and forms reflow from one column to desktop grids; the comparison matrix owns its horizontal overflow and does not force page-level scrolling; detail reading surfaces remain opaque or high-opacity and use stable section anchors.
- Special components: Four-slot comparison workspace, structured comparison matrix, shared `UniversityLibrary` browser, `DashboardPageHeader`, `SchoolCrest`, school/program detail cards, `UniversityTargetForm`, `TargetStatusForm`, query-error alerts, guided empty states, and semantic status badges.
- Allowed deviations: Comparison may use a horizontally scrollable matrix because side-by-side values are its primary task. Detail may repeat the university name as an H3 identity heading beneath the route H2. The Group A files in this packet are shared components used across the primary + deep pages, not standalone page archetypes; they inherit the containing page’s hierarchy, state, and density rules.
- Accessibility risks: Duplicate or skipped headings; comparison overflow obscuring keyboard focus; icon-only destructive controls without names; decorative icons exposed to assistive technology; placeholder-only form fields; unlabeled selects; missing focus indicators; errors rendered as valid empty states; errors announced only as polite status; and status communicated by color alone.
- Acceptance criteria: Page content starts at H3 beneath the shell/page H1–H2; all interactive controls have visible `focus-visible` treatment; form controls have persistent labels; icon-only controls have accessible names and decorative icons use `aria-hidden="true"`; database errors use `role="alert"` and remain distinct from valid empty or not-found states; loading is supplied by the study-abroad route boundary and permission is enforced by the study-abroad layout/auth boundary; comparison overflow stays local; status retains visible text; and no owned source uses raw hex/RGB(A) values or the removed `--app-*` namespace.
