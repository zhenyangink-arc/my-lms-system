# 韩国语一级期中、期末与结课认证独立实施方案

> 本文是一份可以脱离其他路线图独立执行的产品与开发方案。它以项目现有的韩国语一级教材、章节考试、阶段考试、作业布置、考试提交、人工批改、成绩发布、巩固中心、错题中心和“今日学习”聚合能力为基础，补齐期中考试、期末考试、结课资格判定、证书颁发以及未达标补学闭环。本文是实施方案，不代表相关功能已经完成。

## 1. 最终目标

建立完整且可追溯的韩国语一级结课链路：

```text
16章教材学习
→ 章节作业与章节考试
→ 4套阶段考试
→ 期中考试
→ 期末考试
→ 结课资格计算
→ 未达标补学／补考
→ 重新计算资格
→ 机构审核并颁发证书
→ 学生查看长期有效的结课记录
```

完成后，系统应能明确回答：

1. 学生是否满足韩国语一级结课标准。
2. 如果不满足，具体缺少哪一项学习或考试证据。
3. 学生应该进入哪个真实页面补学或补考。
4. 结课判定采用了哪个课程版本、政策版本和成绩快照。
5. 谁在什么时间颁发、撤销或重新颁发了证书。
6. 历史课程、试卷或政策变化是否影响既有证书。

## 2. 关键决策

本方案冻结以下产品与技术决策：

- 不新建网络端口。
- 不新建与现有作业考试中心竞争的考试系统。
- 期中和期末继续使用现有标准母卷、发布、布置、提交和批改链路。
- 结课认证作为韩国语一级课程结果，不成为新的一级应用。
- 学生证书入口放在现有成绩／学习记录范围内。
- 平台负责人制定并发布结课标准。
- 机构负责人只能按已发布标准审核本机构学生并颁发证书。
- 老师可以查看资格明细、推荐补学和发起补考，但不能修改平台标准。
- 学生只能查看自己的资格、缺口和证书。
- 已颁发证书保存不可变快照，不随以后成绩、政策或课程内容变化而改写。
- 自动计算“符合资格”不等于自动颁发证书；第一版保留机构审核。
- 正式音频制作不在本方案范围内，临时音频不得被显示为正式录音。
- 不删除现有章节小测、章节考试、阶段考试、提交记录或历史成绩。

## 3. 当前基础

项目已经具备以下可复用能力。

### 3.1 教材与练习

- 韩国语一级第1—16章智能教材。
- 每章核心词汇及韩文音标。
- 每个词汇至少一轮练习。
- 每个语法至少两轮练习。
- 每章听、说、读、写学习活动。
- 章节巩固、专项训练和错题复习。
- 学习进度、跨设备保存和首页任务聚合。

### 3.2 标准试卷治理

现有 `assessment_papers`、`assessment_paper_questions` 和答案快照体系已经支持：

- 平台标准母卷。
- 草稿、发布、停止提供和历史版本。
- 发布前质量检查。
- 发布后内容锁定。
- 复制为新版本。
- 机构只能看到平台已发布试卷。
- 平台负责人独占发布权。

### 3.3 考试投递

现有 `learning_assignments` 体系已经支持：

- 老师选择标准母卷。
- 班级或指定学生投递。
- 开始时间和截止时间。
- 允许迟交。
- 最大提交次数。
- 题目和选项随机。
- 成绩公开时间。
- 补考卷、补考名单和补考时间。
- 最高分、最新分或加权分补考政策。

### 3.4 提交与批改

现有提交体系已经支持：

- 草稿保存。
- 幂等提交。
- 权威考试时间。
- 客观题自动判分。
- 口语录音和写作答案保存。
- 口语、写作分项量规批改。
- 批改完成和显式成绩发布。
- 学生查看评分明细和老师反馈。
- 错题和补练入口。

### 3.5 已有考试内容

- 第1—16章正式章节考试草稿。
- 4套阶段考试草稿：第1—4章、第5—8章、第9—12章、第13—16章。

当前主要缺口是：

- 没有韩国语一级期中考试标准母卷。
- 没有韩国语一级期末考试标准母卷。
- 没有独立的结课政策版本。
- 没有学生结课资格快照。
- 没有证书颁发、撤销和查验记录。
- 未达标项目还没有形成统一的补学清单。

## 4. 范围与非目标

### 4.1 本方案包含

- 1套期中考试标准母卷。
- 1套期末考试标准母卷。
- 期中、期末试卷质量检查扩展。
- 结课政策模型和版本管理。
- 学生结课资格计算。
- 资格证据快照。
- 未达标原因和补学深链。
- 机构审核和证书颁发。
- 证书撤销与重新颁发。
- 学生端结课状态和证书页面。
- 老师、机构和平台查看范围。
- 与“今日学习”、成绩、记录和错题的连接。
- 数据迁移、权限、测试和上线方案。

### 4.2 本方案不包含

- 正式录制全部教材和考试音频。
- AI口语自动评分。
- AI写作自动评分。
- 自动生成未经平台审核的正式试题。
- 对外部政府或学校证书系统进行对接。
- 区块链证书。
- 收费、支付或证书邮寄。
- 韩国语二级课程建设。
- 重做现有学生首页。
- 重做现有作业考试中心。
- 重写已经稳定的提交和判分状态机。

## 5. 角色与权限

## 5.1 平台负责人

可以：

- 创建、审核和发布期中、期末标准母卷。
- 创建并发布结课政策版本。
- 设置结课必修项和最低标准。
- 停止旧政策用于新学生。
- 查看跨机构资格与证书汇总。
- 在异常情况下撤销证书。
- 查看全部证书审计记录。

不能：

- 覆盖已经颁发证书中的成绩快照。
- 静默修改已经生效的政策版本。
- 直接修改学生历史答卷。

## 5.2 机构负责人

可以：

- 查看平台已发布的结课政策。
- 查看本机构学生资格明细。
- 审核符合资格的学生。
- 颁发本机构证书。
- 因明确原因申请或执行撤销。
- 查看本机构未达标分布。

不能：

- 修改平台结课标准。
- 降低及格线后绕过平台政策。
- 查看其他机构学生。
- 为不符合资格的学生强制颁发普通证书。

如业务以后确实需要例外颁发，应另建“平台特批”流程，第一版不包含。

## 5.3 老师

可以：

- 查看自己负责学生的资格明细。
- 查看缺失课程、作业、考试和批改项目。
- 向学生推荐对应章节巩固或错题复习。
- 按现有规则布置补考。
- 完成口语和写作人工批改。
- 向机构提交结课审核建议。

不能：

- 颁发或撤销证书。
- 修改结课政策。
- 修改已经发布的正式成绩。
- 查看无教学关系的学生。

## 5.4 学生

可以：

- 查看自己的期中、期末任务和成绩。
- 查看自己的结课资格完成度。
- 查看每项未达标原因。
- 进入对应真实页面补学或补考。
- 查看和下载自己的已颁发证书。
- 查看证书状态和颁发时间。

不能：

- 查看其他学生资格或证书。
- 查看试卷答案密钥。
- 修改资格快照或证书状态。
- 在成绩未发布前读取内部评分。

## 6. 期中考试设计

## 6.1 覆盖范围

期中考试覆盖第1—8章，重点检查：

- 韩文字母、问候和自我介绍。
- 日常地点与存在表达。
- 日常活动和过去经历。
- 购物、数量和金额。
- 天气与建议。
- 周末计划与邀约。
- 前8章核心词汇和语法的综合运用。

## 6.2 建议结构

建议考试时间为75分钟，满分100分：

| 能力 | 建议题量 | 分值 | 判分方式 |
|---|---:|---:|---|
| 词汇 | 10—12 | 15 | 自动判分 |
| 语法 | 10—12 | 20 | 自动判分为主 |
| 听力 | 5—7 | 15 | 自动判分 |
| 口语 | 1—2 | 15 | 老师量规批改 |
| 阅读 | 2篇、6—8题 | 20 | 自动判分 |
| 写作 | 1题 | 15 | 老师量规批改 |
| 合计 | — | 100 | 混合判分 |

## 6.3 内容原则

- 不直接拼接第1—8章章节卷。
- 每道题必须标记能力、来源章节和知识点。
- 至少覆盖6个不同章节。
- 语法题应包含跨章节辨析。
- 阅读和听力使用新的综合语境。
- 口语和写作不得复制教材示范答案。
- 客观题必须有权威答案和解析。
- 主观题必须有明确量规和满分约束。
- 临时音频必须标记 `temporary`，不得标记为 `formal`。

## 6.4 稳定标识

建议母卷代码：

```text
EX-K1-MID-V1
```

后续修改不覆盖V1，而是复制为：

```text
EX-K1-MID-V2
```

## 7. 期末考试设计

## 7.1 覆盖范围

期末考试覆盖第1—16章，重点检查：

- 全册核心词汇和高频语法。
- 日常生活、校园、购物、天气、健康、交通、服装和旅行等场景。
- 多轮对话和跨句理解。
- 综合阅读和信息整合。
- 口语任务完成能力。
- 有结构的基础写作能力。

## 7.2 建议结构

建议考试时间90分钟，满分100分：

| 能力 | 建议题量 | 分值 | 判分方式 |
|---|---:|---:|---|
| 词汇 | 12—15 | 15 | 自动判分 |
| 语法 | 12—15 | 20 | 自动判分为主 |
| 听力 | 7—9 | 15 | 自动判分 |
| 口语 | 2 | 15 | 老师量规批改 |
| 阅读 | 3篇、8—10题 | 20 | 自动判分 |
| 写作 | 1—2 | 15 | 老师量规批改 |
| 合计 | — | 100 | 混合判分 |

## 7.3 内容原则

- 前8章与后8章均需有明确覆盖。
- 至少覆盖12个不同章节。
- 不得仅扩大期中卷题量形成期末卷。
- 至少包含一组跨章节语法辨析。
- 至少包含一个综合生活任务。
- 听力、阅读材料必须与题目证据一致。
- 口语和写作量规总分必须与题目分值一致。
- 所有题目必须保存发布时快照。

## 7.4 稳定标识

建议母卷代码：

```text
EX-K1-FIN-V1
```

版本升级规则与期中卷一致。

## 8. 试卷发布质量门槛

期中和期末发布前必须检查：

- 母卷代码符合固定规则。
- 总分等于100分。
- 时长、及格线和重复提交规则存在。
- 六项能力全部存在。
- 每项能力分值符合平台配置。
- 章节覆盖达到最低数量。
- 客观题有答案和解析。
- 主观题标记为人工批改。
- 口语、写作量规与题目分值一致。
- 听力题具有文本和音频状态。
- `pending` 或缺失音频不能被误判为正式音频。
- 不存在重复题干和完全重复选项。
- 题目数量与母卷快照一致。
- 题目分值合计与母卷总分一致。
- 试卷仍处于草稿时不对机构可见。

质量检查失败时必须返回逐条问题，不得只显示“判定配置尚未完成”。

## 9. 结课政策模型

结课标准不能硬编码在页面组件中，应建立可版本化政策。

建议新增：

### 9.1 `course_completion_policies`

| 字段 | 用途 |
|---|---|
| `id` | 政策主键 |
| `student_app_id` | 所属学习应用 |
| `course_id` | 韩国语一级课程 |
| `policy_code` | 稳定代码，例如 `K1-COMP-V1` |
| `version` | 政策版本 |
| `title` | 自然语言标题 |
| `status` | `draft/published/retired` |
| `effective_from` | 生效时间 |
| `effective_until` | 可选失效时间 |
| `requirements` | 结构化必修项与阈值 |
| `created_by` | 创建人 |
| `published_by` | 发布人 |
| `published_at` | 发布时间 |
| `created_at` | 创建时间 |
| `updated_at` | 更新时间 |

### 9.2 第一版政策建议

阈值应保存到 `requirements`，不要散落为页面常量。建议初始值：

| 项目 | 建议标准 |
|---|---|
| 教材 | 16章必修学习全部完成 |
| 必修作业 | 已布置的必修作业全部提交并完成批改 |
| 正式章节考试 | 平台政策指定的最低完成数量 |
| 阶段考试 | 4套均完成并发布成绩 |
| 期中考试 | 成绩已发布且达到政策及格线 |
| 期末考试 | 成绩已发布且达到政策及格线 |
| 口语写作 | 所有认证所需主观题均完成批改 |
| 总体成绩 | 达到政策规定的综合成绩 |
| 严重未完成项 | 不存在阻断结课的必修缺口 |

是否要求16套正式章节考试全部通过，应由平台负责人在政策中确认，不能由开发人员自行决定。

### 9.3 政策发布规则

- 只有平台负责人可以发布。
- 已发布政策内容不可直接修改。
- 修改标准必须复制为新版本。
- 新版本只影响其生效范围内的新资格计算。
- 已颁发证书继续引用旧政策快照。
- 同一课程同一时间只能有一个默认生效政策。

## 10. 资格计算模型

建议新增：

### 10.1 `student_course_completion_evaluations`

| 字段 | 用途 |
|---|---|
| `id` | 资格计算主键 |
| `tenant_id` | 机构隔离 |
| `student_id` | 学生 |
| `student_app_id` | 学习应用 |
| `course_id` | 韩国语一级课程 |
| `policy_id` | 采用的政策 |
| `policy_version` | 政策版本快照 |
| `status` | 资格状态 |
| `eligible` | 是否符合资格 |
| `overall_score` | 可选综合成绩 |
| `requirements_snapshot` | 标准快照 |
| `evidence_snapshot` | 实际学习证据快照 |
| `missing_requirements` | 未达标项目 |
| `evaluated_at` | 计算时间 |
| `evaluation_version` | 算法版本 |
| `created_at` | 创建时间 |
| `updated_at` | 更新时间 |

建议状态：

```text
not_ready             尚未达到计算条件
pending_grading       存在等待人工批改项目
not_eligible          已计算但未达标
eligible              已符合资格，等待机构审核
superseded            已被更新计算替代
```

### 10.2 证据来源

资格计算应读取真实来源，不复制业务判断：

| 证据 | 权威来源 |
|---|---|
| 教材完成 | 课程、课时、章节与教材进度表 |
| 作业完成 | `learning_assignments`、`learning_submissions` |
| 章节／阶段／期中／期末 | 标准母卷代码、投递任务和已发布成绩 |
| 主观题批改 | 提交状态机与成绩发布时间 |
| 巩固与错题 | 仅作为补学证据，第一版不直接替代正式考试 |
| 老师评价 | 学习记录备注，仅作辅助信息 |

### 10.3 计算原则

- 只使用已发布成绩。
- 不读取未发布暂定分。
- 不把“已提交待批改”视为考试完成。
- 取哪一次成绩必须遵循任务补考政策。
- 不按标题模糊匹配决定考试类型。
- 优先使用标准母卷代码和 `source_paper_id`。
- 同一必修项不能重复计数。
- 计算结果必须可重复、可审计。
- 每次计算记录算法版本和时间。
- 证书颁发后不再重写其证据快照。

## 11. 未达标原因模型

`missing_requirements` 每项建议包含：

```ts
type CompletionRequirementGap = {
  key: string;
  category:
    | "course"
    | "assignment"
    | "chapter_exam"
    | "stage_exam"
    | "midterm_exam"
    | "final_exam"
    | "manual_grading"
    | "overall_score";
  title: string;
  status: "missing" | "in_progress" | "failed" | "pending_grading";
  currentValue?: number;
  requiredValue?: number;
  sourceId?: string;
  href?: string;
  reason: string;
};
```

禁止把颜色、图标和CSS类保存进数据库。

每个缺口必须提供明确自然语言说明，例如：

- “第12章教材尚未完成”。
- “第二阶段考试尚未布置”。
- “期中考试口语题正在等待老师批改”。
- “期末成绩为58分，政策要求60分”。

## 12. 补学与补考闭环

### 12.1 补学规则

| 缺口 | 推荐动作 |
|---|---|
| 教材未完成 | 进入最后未完成章节 |
| 作业未完成 | 进入对应作业 |
| 某章能力薄弱 | 进入该章巩固详情 |
| 专项能力薄弱 | 进入指定能力专项训练 |
| 存在错题 | 进入对应来源的错题复习 |
| 考试未通过 | 老师布置补考或重新学习 |
| 等待人工批改 | 显示等待状态，不重复要求学生作答 |

### 12.2 补考规则

继续复用现有补考能力：

- 指定补考卷。
- 指定学生名单。
- 设置开始和截止时间。
- 选择最高分、最新分或加权分。
- 补考卷必须与首次考试属于同一应用和考试类型。
- 补考完成并发布成绩后重新计算资格。

### 12.3 与今日学习连接

- 已经布置的期中、期末和补考自动进入现有作业考试聚合。
- 未布置考试不能伪造为学生可执行任务。
- 资格缺口只在存在真实深链时提供“去完成”。
- `pending_grading` 只显示状态，不生成重复提交任务。
- `eligible` 后首页可显示“等待机构审核”，但不抢占即将截止考试。
- 证书颁发后显示一次结果提醒，之后进入成绩／记录页面长期查看。

## 14. 证书状态机

```text
符合资格
→ 等待机构审核
→ 已颁发
→ 正常有效
```

异常流程：

```text
已颁发
→ 有明确撤销原因
→ 已撤销
→ 修正问题并重新审核
→ 重新颁发新证书
```

规则：

- 撤销不删除原证书。
- 重新颁发生成新编号。
- 新证书关联原证书。
- 已撤销证书公开查验时必须显示“已撤销”。
- 不能把撤销记录物理删除。
- 学生姓名更正不直接覆盖历史证书，应走重新颁发。

- 证书名称、学生姓名、课程、颁发机构和日期清晰可读。
- 详细标准放在提示或展开区域，不重复占据正文。

## 17. 资格重新计算触发点

以下事件发生后应刷新资格：

- 教材章节完成。
- 必修作业成绩发布。
- 章节、阶段、期中或期末成绩发布。
- 口语写作人工批改完成并发布。
- 补考最终成绩发布。
- 平台发布新的结课政策。
- 机构管理员手动请求重新计算。

实现原则：

- 业务提交不得被资格计算失败阻断。
- 先完成权威业务写入，再异步或安全刷新资格。
- 同一学生同一政策并发刷新必须幂等。
- 不允许每次打开页面都重算全部学生。
- 批量刷新必须用集合查询，不逐学生循环请求。

## 18. 安全与RLS

所有新表必须启用并强制RLS。

### 18.1 学生

- 只能读取自己的资格和证书。
- 不能直接写资格、证书和审计表。
- 不能读取内部撤销备注之外的敏感管理信息。

### 18.2 老师

- 只能读取真实教学关系范围内学生。
- 不能颁发、撤销或修改证书。
- 不能读取其他机构。

### 18.3 机构负责人

- 只能读取和处理本机构证书。
- 只能对符合资格记录执行颁发。
- 撤销必须填写原因。

### 18.4 平台负责人

- 可以发布政策并查看全局汇总。
- 高风险证书操作仍须服务端重新校验。
- 平台权限不能只靠前端按钮隐藏。

### 18.5 公开查验

如后续开放公开查验，应使用专用RPC，只返回：

- 证书编号。
- 状态。
- 脱敏姓名或经业务确认可公开的姓名。
- 课程名称。
- 颁发机构。
- 颁发日期。

不得返回学生ID、邮箱、答卷、详细成绩或内部备注。

## 19. 历史数据与不可变性

- 已发布母卷不直接修改。
- 历史提交继续引用原试卷快照。
- 资格计算保存政策和证据快照。
- 证书保存颁发时快照。
- 新政策不自动撤销旧证书。
- 课程改名不覆盖旧证书课程名称。
- 学生姓名更正通过重新颁发处理。
- 证书撤销只改变状态并追加事件，不删除记录。

## 20. 性能要求

- 单个学生资格计算使用固定数量集合查询。
- 机构列表使用聚合RPC，不逐学生加载完整答卷。
- 平台汇总按机构聚合，不逐机构循环。
- 学生页面只返回自己的资格摘要和必要证据。
- 证书PDF或打印内容按需生成。
- 题目答案密钥不进入资格计算响应。
- 高频汇总后续可使用物化快照，但第一版不提前复杂化。

## 21. 错误与空状态

必须区分：

- 尚未发布结课政策。
- 学生未开通韩国语应用。
- 尚未开始韩国语一级课程。
- 存在等待人工批改项目。
- 资格计算暂时失败。
- 不符合资格。
- 符合资格等待审核。
- 证书已颁发。
- 证书已撤销。

禁止统一显示“暂不可用”或“配置尚未完成”。错误信息应指出责任方和恢复动作。

- [ ] 结课政策可版本化。
- [ ] 资格只使用权威且已发布数据。
- [ ] 待批改和未达标得到正确区分。
- [ ] 每个缺口有明确原因。
- [ ] 资格计算可重复、可审计、幂等。

### 证书

- [ ] 不符合资格不能颁发。
- [ ] 证书编号全局唯一且不可预测。
- [ ] 证书保存政策和成绩快照。
- [ ] 撤销不删除历史。
- [ ] 重新颁发生成新编号并关联旧证书。
- [ ] 学生能够查看自己的证书。

### 权限与数据

- [ ] 平台、机构、老师和学生权限边界清晰。
- [ ] 机构之间完全隔离。
- [ ] 未发布成绩和答案不泄露。
- [ ] 已发布母卷和证书快照不可静默改写。
- [ ] 聚合查询无明显瀑布。

### 体验

- [ ] 今日学习可以显示真实期中、期末和补考任务。
- [ ] 未达标学生知道下一步去哪。
- [ ] 待批改不会被显示为提交失败。
- [ ] 手机端无横向滚动。
- [ ] 状态同时使用图标和文字。
- [ ] 证书支持清晰打印。

## 27. 完成定义

本项目只有在以下真实业务闭环成立时才算完成：

```text
平台负责人发布期中、期末和结课政策
→ 机构老师布置考试
→ 学生作答并提交
→ 老师完成口语写作批改并发布成绩
→ 系统计算结课资格
→ 未达标学生获得补学／补考路径
→ 达标后机构负责人审核并颁发证书
→ 学生查看证书
→ 历史证据、政策版本和操作审计均可追溯
```

仅创建页面、仅插入试卷草稿、仅显示“符合资格”，都不等于完成。

## 28. 推荐的第一项执行任务

期中卷通过内容检查后，再写入标准母卷草稿。不要在内容结构尚未冻结时同时开发证书页面。
