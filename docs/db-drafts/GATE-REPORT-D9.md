# Architecture Gate 报告：D9（大学课程专业可见范围）

> **性质：作者自审，不是独立审查。** 与 `GATE-REPORT-D5-D7-D8.md` 同样的限制：写草稿的同一个 Claude 会话按 `CODEX_SUPERVISOR.md` 的 Gate 要求自查，需要独立 Gate 补上独立性。
> 日期：2026-10-01。验证均在隔离验证库完成（`tools/rehearse-d9.sh`），没有碰真实库。设计背景见 `../university-major-structure-design.md`。

## 1. 结论：ALLOW（有条件）

可以进入“整理为正式迁移”的下一步，前提是满足第 6 节的条件。D9 **不依赖 D5、D7、D8，也不被它们依赖**，可以单独评审、单独迁移。

## 2. 要解决的问题

产品决定（2026-10-01）：大学课程内容按专业区分；有跨专业的公共课；学生只看自己专业；大学英语、大学数学留在各自应用。现有数据模型里一门课只属于一个分类、学生授权按应用而不是按专业，没有“学生所属专业”，也没有“公共课对哪些专业可见”。

## 3. 推荐方案与被否决的方案

**推荐**：专业 = 大学课程下的二级分类；公共课放进“公共课组”（同样是二级分类），用可见模式（`major` / `shared` / `public`）决定谁能看；学生所属专业单独一张表。课程仍只属于一个分类。

| 被否决的方案 | 原因 |
|---|---|
| `course_category_links`：一门课挂多个专业 | 目录、分类、专业、课程、课时、资料下载、当前课程等约 10 处按 `courses.category_id` 取课，多对多会牵动所有共用页面与课时资料下载的授权，风险高 |
| 按专业复制课程 | 进度、成绩、作业都按课程 id 记，复制后同一门课的进度互不相通 |
| 给 `course_categories` / `courses` 加 `major` 或 `subject` 列 | 改核心共用表；与“学科键 = `student_app_id`”的规则冲突 |
| 在 `courses` / `lessons` 的读取策略里按专业过滤（RLS 下沉） | 改共用策略，波及韩语；本次内容不属于保密数据，先只在应用层过滤（见第 6 节条件 1） |

## 4. 改动清单（全部为新增，不改既有对象）

| 类别 | 对象 | 说明 |
|---|---|---|
| 新表 | `university_category_access` | 二级分类的可见模式；没有记录等同 `major` |
| 新表 | `university_category_major_links` | `shared` 模式的公共课组关联哪些专业 |
| 新表 | `student_major_enrollments` | 学生所属专业（机构级，可多个） |
| 触发器 | 4 个校验 / 清理触发器 | 只能是大学课程应用下的二级分类；只有 `shared` 能关联专业，关联的必须是 `major` 模式的分类；学生必须是本机构大学课程应用的学生；已有学生或关联的专业不能改成其他模式（INSERT 与 UPDATE 都查） |
| 函数 | `university_category_scope()` | 当前用户可见的二级分类；学生受限，教职人员与平台账号不受限；`security definer`，`search_path=''` |
| 函数 | `set_university_category_access()` | 仅平台负责人 / 平台管理员；整体替换关联，原子 |
| 函数 | `set_student_major_enrollment()` | 需要机构里“管理学生”能力；写入当前机构 |
| RLS / 授权 | 三张新表 | `authenticated` 只读（学生只能读自己的专业记录；教职人员按“管理学生 / 查看分析”能力读）；写入只经上面两个函数 |

未改：所有既有表、既有函数、既有策略（`rehearse-d9.sh` 在执行前后比对了 `public` 全部策略与 `public` / `private` 全部既有函数定义的指纹，一致）。

## 6. 自审发现与条件

**已修正的缺陷**（演练中发现）：没有可见模式记录的专业（默认 `major`）首次写成其他模式时走 INSERT，绕过了“已有学生 / 关联时不能改模式”的保护；已改为 INSERT 与 UPDATE 都检查，测试 6a、6b 覆盖。

**进入正式迁移前的条件：**

1. **可见范围没有下沉到 RLS（需 Gate 明确接受或要求下沉）。**同机构成员绕过页面、直接用客户端读取平台课程表，仍能读到其他专业的课程与课时。当前判断：大学课程内容不属于保密数据，只是“默认不展示”，所以只在应用层过滤并在路由层拦截。如果要求真正隔离，需要改 `courses` / `lessons` / `course_categories` 的读取策略，那是共用策略改动，需单独设计与回归。
2. **迁移顺序**：编号排在 Codex 线迁移之后；D9 与 D5/D7/D8 无依赖，可以不同批次。
3. **上线开关**：D9 迁移后大学课程应用仍是 `coming_soon`，机构开放前学生进不去；没有数据迁移。

**已知且接受的边界：**

- 二级分类被改挂到别的一级分类或移出大学课程应用后，旧的可见模式 / 关联行会残留，但 `university_category_scope()` 联结时要求分类仍是大学课程下的二级分类，残留行无副作用。
- 回滚（down）会删除三张表里的数据；上线后回滚需先确认可以丢弃。
- `university_category_scope()` 用 `private.current_tenant_id()`（用户的默认 / 最早活跃机构）；一个账号属于多个机构时，范围按该机构计算，与现有各处一致。
- 学生专业状态只有 `active` 计入可见范围；`completed`（毕业 / 修完）后该专业不再可见，如需保留要另行决定。
