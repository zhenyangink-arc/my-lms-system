# 大学课程：专业结构设计（只分析，未实现数据库改动）

日期：2026-10-01。状态：**方案 A 已实现（学生端文案）；产品已回答三个问题（见第 6 节），据此起草了 D9 草稿，尚未在验证库执行。**

## 1. 现状（方案 A：专业 = 二级分类）

大学课程（一级分类）→ 专业（二级分类）→ 课程 → 课时。学生端文案由清单字段 `student.catalogSubcategoryLabel` 提供。没有数据库改动。

已知边界（来自表结构，验证库 2026-10-01 核对）：

- `courses.category_id` 只有一个值，**一门课只能放进一个专业**。
- 课程被大量表引用（`lesson_progress`、`grade_items`、`learning_assignments`、`library_resources`、结课资格等）：进度、成绩、作业都按课程 id 记。若为了跨专业而复制课程，同一门课会出现多份互不相通的进度与成绩。
- 学生授权按应用（`student_app_enrollments`）记，没有“学生所属专业”；课程读取策略也不看专业。所以学生能看到应用内**所有**专业。

## 2. 要产品回答的三个问题（决定是否需要升级）

1. 有没有跨专业的公共课（高等数学、大学物理、思政、计算机基础等）？大概占多少？
2. 学生是否只看自己专业的内容 / 老师是否按专业分配？
3. 大学英语、大学数学留在 `english` / `math` 应用（2026-09-30 的决定），还是在大学课程里也出现？

## 3. 升级路径（任一项都属于数据库 / RLS 改动，必须走 Architecture Gate）

**方案 B：课程可挂多个专业。** 新增关联表 `course_category_links(course_id, category_id, sort_order, is_required)`，课程仍只有一份（`courses.category_id` 作为“归属专业”保留），进度与成绩不变。目录页按“归属 + 关联”取课程。适合：公共课多、但所有学生都能看全部专业。

**方案 C：学生按专业可见。** 在 B 之上新增 `student_major_enrollments(tenant_id, student_id, category_id, status)`，课程读取与目录页按学生所属专业过滤（公共课对所有专业开放）。涉及 RLS 与老师分配，是最大的一档。适合：学生只应看到自己专业。

**不建议**：按专业复制课程（进度、成绩分裂）；或给 `subject` 之外再加“专业”维度字段（与平台“学科键 = student_app_id”的规则冲突）。

## 4. 决策表

| 回答 | 做什么 |
|---|---|
| 没有公共课，学生可看全部专业 | 保持方案 A；只需把管理端叫法改成“专业” |
| 有公共课，学生可看全部专业 | 方案 B |
| 学生只看自己专业 | 方案 C（含 B） |

## 5. 不依赖回答、可以先做的事

- 管理端课程结构里把“分类 / 下级内容”显示成“专业”（同样用清单标签，不涉及数据库；改的是共用的结构编辑页，需要先确认它对韩语 / 英语 / 数学文案不变）。

## 6. 产品回答与 D9 草稿（2026-10-01）

回答：① 有跨专业公共课；② 学生只看自己专业；③ 大学英语、大学数学留在各自应用。对应第 4 节的“方案 C（含 B）”，但实现上做了一处调整：

- **不做“课程挂多个专业”。** 现有查询在目录、分类、专业、课程、课时、资料下载、当前课程、顶栏搜索等约 10 处都按 `courses.category_id` 取课，改成多对多会牵动所有共用页面，风险高。
- **改为“公共课组关联专业”**：公共课放进二级分类（公共课组），课程仍只属于一个分类。每个二级分类有可见模式：`major`（默认，仅选了该专业的学生可见）、`shared`（选了任一关联专业可见，如“理工公共课”）、`public`（所有学生可见，如“通识课”）。精确表达“高数只给理工科”，又不动课程表与共用页面查询。
- 草稿 `D9-university-major-access.{up,down,test}.sql`：3 张新表（可见模式、公共课组关联专业、学生所属专业，可多个）、`university_category_scope()`（学生受限、教职人员与平台账号不受限；没选专业只剩 `public`）、2 个带权限校验的写入 RPC（平台负责人设置可见模式；有“管理学生”能力的机构账号设置学生专业）。新表 authenticated 只读，写入只经 RPC；**不改任何既有表、函数、策略**。
- 演练脚本 `tools/rehearse-d9.sh`：执行前后比对共用策略与函数指纹、跑 `D9` 测试（40 余项）、回滚后再比对。**还没有执行过**——写入验证库的命令被权限分类器拒绝，需要用户确认后才能运行。
- 限制（需 Gate 决定）：可见范围由应用层按 `university_category_scope()` 过滤并在路由层拦截，没有下沉到课程表的读取策略；同机构成员直接用客户端读平台课程表仍然可行（与现状一致，内容不属于保密数据）。
- 应用层待做（依赖 D9 在验证库跑通后才能浏览器验证）：① 目录页与专业列表按可见范围过滤，专业路由层拦截不可见专业（其下课程、课时页同受保护）；② 机构“学生与教学分配”里为大学课程学生选择专业；③ 平台负责人在课程结构里设置可见模式与关联专业；④ 管理端叫法改成“专业”。
