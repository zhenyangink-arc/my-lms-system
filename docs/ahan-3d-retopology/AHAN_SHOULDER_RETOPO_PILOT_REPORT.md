## 一、拓扑构建方法与技术检查

### 1.1 构建方法（与最初设想不同，实际执行时做了修正）

最初尝试"只在左肩做3圈切割 → 复制该区域 → 镜像 → 删除右肩旧区域 → 按距离焊接缝合"，实测发现Instant Meshes左右两侧的**拓扑连接方式并非严格镜像**（虽然顶点位置对称度99.2%以上，但连接关系/三角剖分方向不完全对称），导致按距离焊接始终无法收敛到0非流形（测试了0.001-0.008m多档阈值，8mm容差下仍残留148条非流形边），"Bridge Edge Loops"桥接也因两侧边界元素数量不相等而失败。

**改用的方法**：不做复制+镜像+焊接，而是用垂直于`upper_arm`骨骼轴向的3个平面，分别在左肩和右肩的原生拓扑上直接做`bisect_plane`切割（切割参数完全镜像：位置和法向的X分量取负）。这个方法不移动任何已有顶点、不需要焊接缝合，因为切割直接发生在原始表面上。

### 1.2 静态技术检查结果

| 指标 | 修复后基础网格(v01) | A1肩部拓扑构建后 |
|---|---|---|
| 顶点数 | 15,230 | 15,390 |
| 面数 | 15,606 | 16,005 |
| 四边面占比 | 95.16% | 92.29% |
| 非流形边 | 0 | **0** |
| 非流形顶点 | 0 | **0** |
| 网格岛数量 | 1 | **1** |
| 自相交三角对 | 0 | **0** |
| 左右对称度(1cm容差) | 99.22% | **99.23%**（几乎未变，因为切割不移动原有顶点位置） |

左肩3圈切割产生边数：26/31/32（躯干侧过渡环/主环/上臂侧过渡环）；右肩对应：25/27/30。**边数不完全相等属于预期内**——两侧切割位置严格镜像对称，但底层原生拓扑密度略有差异，边数差异不影响环的功能位置和对称性。

### 1.3 外观检查

正面/45°/侧面静态渲染与切割前对比：整体轮廓、三根头发、耳朵、五官、拳套手、马甲可见轮廓、手臂粗细均无可见变化（切割方法本身不移动顶点位置，从原理上就不会改变外观）。

### 1.4 肩部Edge Flow线框检查

线框特写显示3圈切割在实际曲面上形成了清晰、位置精确对称的横截环（可见对角栅格中出现的星形过渡点，是切割线与原有斜向四边面网格相交产生的正常三角化，不是缺陷）。

**结论：拓扑构建部分——通过。**

## 二、临时Rig压力测试

### 2.1 测试骨架

新建仅用于本次验证的临时骨架（25根deform骨，坐标取自rig-v01验证过的静止姿态数据），**不继承rig-v01的旧网格、旧权重**。权重用Blender自动骨骼热力学权重全新计算，再做了一次基于距离的裁剪（超出各骨骼合理半径的权重清零并重新归一化）——这仍然是"临时测试权重"，不是正式手绘权重。

### 2.2 第一轮测试：纯自动权重 —— 严重失败

第一轮用未加裁剪的纯自动权重测试58°抬手，结果**远比rig-v01已知的问题更严重**：不仅马甲/腹部被拖拽拉宽，连双腿都被明显拉扯变形成漏斗状——证明纯自动权重完全不可用，问题不在拓扑本身，而是权重计算范围过大（骨骼热力学权重在这种四肢紧贴躯干的矮胖角色上容易大范围扩散）。

### 2.3 第二轮测试：距离裁剪权重 —— 部分改善但未完全达标

把肩部/上臂骨骼的权重影响半径裁剪到贴合实际切割范围（0.085m）后重新测试：**双腿不再被拖拽**（裁剪有效解决了远端扩散问题），但**马甲与手臂交界处仍然出现明显的拉伸/牵丝状变形**（渲染图上清晰可见马甲呈现类似"蝙蝠翼"的斜向拉丝纹路，抬手45°视角和梳头姿态下同样出现）。

### 2.4 量化测量

在腹部33%高度处测量宽度变化：

| 姿态 | 腹部宽度变化 |
|---|---|
| Neutral | 基准值（0.778m） |
| HandsUp（58°） | +3.76% |
| Combing_PreTest（60°，双肩对称施加做压力测试） | +0.20% |

**腹部本体的宽度变化幅度其实不大**（+3.76%属于视觉上不易察觉的量级），说明裁剪后的权重已经把"腹部整体膨胀"这个最严重的失效模式控制住了。**但视觉上仍然不合格的是马甲与手臂/肩部交界处的局部拉丝形变**，这个问题量化指标（腹部宽度）测不出来，只有实际看渲染图才能发现——这也印证了方案文档里反复强调的"不能只看数字指标，必须实际看渲染结果"。

### 2.5 与rig-v01旧模型HandsUp的对比

并排对比rig-v01的`AHAN_HandsUp`参考图和本次测试渲染：抬手的**方向和大致幅度是匹配的**（都是双臂外展、手部抬升到接近肩高的"V/W"造型，证明临时骨架的旋转轴设置正确）；但**马甲变形问题两者都存在，本次测试的马甲牵丝拉伸问题在观感上并不比rig-v01更好**，仅仅是"没有把腿也拖拽变形"这一点优于旧模型。

## 四、根因分析——为什么马甲交界处仍然不自然

这**不是A1肩部Edge Loop构建方法本身的缺陷**，而是两个更底层的原因：

1. **马甲（Vest）目前仍然和身体（Body）是同一张网格**。`AHAN_RETOPO_KEY_ZONES_PLAN.md`里已经规划了未来要把Body/Vest分成两个独立网格（对应决策2的"独立材质/独立换装能力"），但那一步还没做。只要马甲和手臂皮肤共享同一套顶点在同一套骨骼权重体系下混合计算，权重算法就没办法区分"这个顶点属于该跟着手臂走的皮肤"还是"这个顶点属于该留在躯干上的马甲布料"——这是一个结构性问题，不是加几圈边线环能解决的。
2. **自动/裁剪权重终究不是手绘权重**。真正干净的肩部形变（尤其是衣物类的形变）在专业流程里几乎总是需要人工精修权重（至少是在自动权重基础上刷几笔），本次为了保持"临时测试权重"的定位没有做这一步，属于预期内的局限，不代表拓扑或方法本身有问题。

- **拓扑构建方法本身：通过，可以固化为A2-A6的执行模板**——用"垂直于骨骼轴向的镜像平面直接切割"替代"复制+镜像+焊接"，实测更稳健（0非流形、0自相交、保持对称、不改变外观），后续肘/腕/髋/膝/颈都建议采用同样的技术路线。
