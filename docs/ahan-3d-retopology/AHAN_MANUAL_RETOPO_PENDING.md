# 阿韩重拓扑 — 待人工介入技术债记录

本文档记录所有经脚本自动化方法反复验证失败、需要后续人工交互式重拓扑工具介入的区域。**禁止**未来把此处标记为`MANUAL_RETOPO_PENDING`的区域，误当作已经完成正式动画拓扑。

## A2-A6 关键区域执行结果总览

按用户指定优先级 A2肘→A3腕→A5膝→A4髋→A6颈 逐一分析后的结论：

| 区域 | 结果 | 根本原因 |
|---|---|---|
| A2 Elbow 肘部 | `MANUAL_RETOPO_PENDING` | 手臂过短，肘部位置已直接融入浑圆腹部，无独立截面 |
| A3 Wrist 腕部 | `MANUAL_RETOPO_PENDING` | 同上，拳套手直接从腹部"长出" |
| A5 Knee 膝部 | `MANUAL_RETOPO_PENDING` | 腿本质是浑圆躯干直接鼓出的短爪状凸起，无独立圆柱段 |
| A4 Hip 髋部 | `MANUAL_RETOPO_PENDING` | 同膝部，躯干与腿之间无过渡区 |
| **A6 Neck 颈部** | **功能性通过（见下方详细报告）** | 头部与躯干之间存在真实、规则的收窄环带（CV仅0.056-0.08），成功完成真正的环切构建，并通过HandsUp量级的形变测试 |

**重要结论**：阿韩四肢（手臂+腿）在当前建模比例下全部是"浑圆躯干直接鼓出的短突起"，没有任何一处存在可供自动环切/重拓扑使用的独立圆柱形截面——这不是算法或分析方法的问题，是角色本身的萌系矮胖比例所致。唯一存在真实规则过渡结构的关键区域是**颈部**（头身连接处），这也是A2-A6中唯一自动化重拓扑真正成功的区域。

## B1 · Eye（眼周）

- **状态**：`MANUAL_RETOPO_PENDING`
- **原因**：当前IM15K打底网格的规则斜向四边面直接穿过眼球/眼眶区域，眼球和周围皮肤是同一套网格里连续的曲面，没有任何独立于皮肤的眼睑结构。这类需求本质上不是"关节环绕"问题，而是需要围绕眼眶做**同心圆环+放射状辐条**的专用面部拓扑（业内标准眼部拓扑），脚本自动构造无法可靠产生这种拓扑意图明确的结构，必须人工交互式布线。
- **参考坐标**：EYE_L≈(0.166,-0.176,0.811)、EYE_R≈(-0.168,-0.175,0.809)（本session从当前网格眼眶区域顶点云质心实测得出，非rig-v01骨骼坐标——眼部在rig-v01中没有对应骨骼）。
- **当前可用版本**：沿用`AHAN_ManualRetopoPrep_v01`基础网格上的原有拓扑（该区域未做任何修改）。
- **详细执行方案**：见[AHAN_MANUAL_RETOPO_EXECUTION_GUIDE.md](AHAN_MANUAL_RETOPO_EXECUTION_GUIDE.md) B1章节。

## A6 · Neck（颈部）— 功能性通过

- **状态**：技术完整性 PASS / 权重 PASS / 形变测试 PASS（18°转头×2方向 + 15°点头 + 18°+18°组合极限测试）/ 常规视觉表现 PASS
- **构建方法**：与A1不同，颈部环切**不需要**删除-重建-缝合两个不匹配边界（头和躯干本来就是同一连续曲面，只是加密切割环），因此规避了A1遇到的"不规则边界N:M缝合"结构性难题。数据显示Z≈0.62-0.70范围内横截面规律性良好（半径变异系数CV=0.056-0.14，24/24射线全部命中），据此在Z=0.62/0.66/0.70三处做mirrored bisect_plane环切。
- **技术指标**：0非流形边/顶点，0自相交，单一连通体，对称性99.25%，quad占比88.5%（局部因bisect与下巴/耳朵等复杂几何相交产生269个多边形，已转为三角扇，非缺陷但非教科书级纯quad）。
- **权重方法**：复用A1验证过的分段距离平滑包络法，沿Z轴在躯干(rigid)与头部(rigid)之间做smoothstep过渡，胸口关键点位移量测量结果为0（无泄漏牵拉）。
- **形变测试**：使用rig-v01真实动作库中的Head_Left/Head_Right(18°)、Nod(约15°等量级)量级测试，另加一个不存在于真实动作库、更极端的18°+18°组合姿态压力测试——所有测试下颈部曲面保持平滑连续，无撕裂、无自相交、无非流形，三角扇区域也能自然跟随形变。
- **诚实说明**：三角扇区域（269处ngon转tri）不是手工精细调整过的教科书级Edge Flow，是bisect_plane与复杂五官/耳朵几何相交后自动三角化的结果——技术上无缺陷，形变测试下表现良好，但如需要极致精细的面部动画（如后续做表情Shape Key），这些三角扇区域可能需要后续人工微调。
- **存档位置**：`retopo-v01/pilot-A6-neck/mesh/`（`AHAN_A6_Neck_Topology.blend` + `AHAN_A6_Neck_TestRig_EnvelopeWeights.blend`）、`retopo-v01/pilot-A6-neck/renders/`、量化数据`neck_cut_report.json`/`neck_deform_report.json`。

## A1 · Shoulder（肩部）

- **状态**：`MANUAL_RETOPO_PENDING`
- **当前可用版本**：`AHAN_A1_Shoulder_Functional_Provisional`（存档于`retopo-v01/pilot-A1-shoulder/mesh/`），**仅为功能可用的临时版本，不是最终动画母模肩部拓扑**。
- **已验证通过的部分**：技术完整性（0非流形/0自相交/单一连通/对称99.49%）、分段距离平滑包络权重方法、HandsUp 58°功能形变测试（腹部/马甲位移0）、常规观察距离视觉表现。
- **未完成的部分**：正式动画Edge Flow——肩窝区域没有真正围绕upper_arm形成受控闭合环，当前是bisect横截线+局部Laplacian平滑的结果，不是真正重组过的拓扑。
- **失败原因**：肩窝处Body/Vest/UpperArm三者在几何上高度不规则融合（马甲贴身、手臂从浑圆躯干直接过渡，无规则圆柱截面可参照），躯干侧的边界形状在数学上不是能围绕手臂轴心简单参数化的规则环。脚本自动"N:M环桥接"方法（欧氏距离选区+Bridge、拓扑连通性洪水填充、射线投射采样+Bridge、手工按比例缝合+绕向修正+角度重排序）经过4轮独立实验，全部产生非流形边或大量自相交，详见[AHAN_SHOULDER_TRUE_LOCAL_RETOPO_REPORT.md](AHAN_SHOULDER_TRUE_LOCAL_RETOPO_REPORT.md)。**已证明不可靠，不再投入时间重复研究同类算法。**
- **未来解决方式优先级**：
  1. Blender人工Poly Build + Shrinkwrap（真人在高模表面上手动画线）
  2. RetopoFlow交互式重拓扑插件（本机未安装，收费，需人工操作）
  3. 其他可视化人工重拓扑工具

- **当前可用版本**：沿用`AHAN_RetopoBase_IM15K_v01`基础网格上的原有拓扑（该区域未做任何修改）。

## A5 · Knee（膝部）

- **状态**：`MANUAL_RETOPO_PENDING`
- **原因**：先前基于远景轮廓渲染（`knee_area_front.png`）误判膝部为"清晰独立悬空的腿"，判定为优先尝试对象。但实际执行bisect环切时，在膝部骨骼坐标周围0.09m半径内**完全没有切到任何面**（`cut_edges=0`），排查发现该骨骼坐标与最近实际网格顶点相距达0.1167m——随后改用近景特写渲染（`knee_diag_front.png`/`knee_diag_wide.png`）直接确认：阿韩的"腿"实际上只是浑圆躯干直接鼓出的一段极短的爪状/脚掌结构，躯干与脚掌之间**没有真正独立的圆柱形大腿/小腿过渡段**可供构建规则环——与A1肩部、A2肘部、A3腕部属于同一类"肢体过短、直接融入浑圆躯干"的结构性问题，且比肩部更严重（连近似的独立管状截面都不存在）。
- **教训**：远景轮廓渲染容易因视角/距离造成"看似独立"的错觉，必须用近景特写渲染才能可靠判断某区域是否真正适合自动环切构建——这条经验补充进方法论，后续A4/A6同样需要近景验证，不能只看远景轮廓。
- **当前可用版本**：沿用`AHAN_RetopoBase_IM15K_v01`基础网格上的原有拓扑（该区域未做任何修改）。
