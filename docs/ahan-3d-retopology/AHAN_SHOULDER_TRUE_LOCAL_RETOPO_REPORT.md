## 一、尝试方法总览（4次迭代，逐一说明失败原因）

### 尝试1：欧氏距离选区 + 删除 + Bridge Edge Loops（插值） —— 失败

**方法**：以肩关节为中心，用纯3D欧氏距离(半径0.16m)选中局部区域，删除后用`bridge_edge_loops`（插值3圈）重新铺面。

**结果**：460条非流形边，3164对自相交。

**根因**：马甲在肩部这个高度本身就贴着身体表面（阿韩的马甲是贴身设计），纯3D距离选区无法区分"这是身体表面"还是"这是贴近的马甲表面"——挖出的洞不是简单的躯干侧+手臂侧两个边界环，混入了马甲边缘的额外边界，Bridge没法正确配对。

### 尝试2：拓扑连通性洪水填充选区 —— 失败（更早放弃）

**方法**：从关节种子面出发，沿网格连通性做洪水填充，遇到预先切好的边界环才停止扩展，试图更精确地只圈住手臂/躯干本体。

**结果**：边界屏障检测有遗漏，填充穿透了整个单一连通网格（选中了16035个面，几乎是全部网格）；另一侧甚至没找到任何边界环。

**根因**：整个网格是单一连通体，只要边界屏障集合有哪怕一条边没被正确识别，洪水填充就会从那个缺口"漏"出去，蔓延到整个网格。这个方法对边界完整性的要求极高，实现中未能保证。

### 尝试3：射线投射采样干净环 + 自动Bridge —— 部分成功但缝合失败

**方法**：放弃在原有网格上选区删除，改为从骨骼轴线出发，向外做360°射线投射，在真实表面上采样出顶点数完全相同(20个)、间距均匀的干净圆环，用于构建无Pole的管状核心区。再删除躯干侧/手臂侧的原网格小圆盘，把干净环通过Bridge缝合到这两个洞口。

**结果**：
- 干净环本身构建成功（半径~5cm，与手臂粗细吻合，0马甲误伤）。
- 中段管状连接（20对20）完全干净。
- 但环（20条边）与原网格洞口边界（44-55条边，数量差2-3倍）用`bridge_edge_loops`自动缝合时，产生了大量又长又不均匀的三角面，实际渲染呈现出明显的尖刺状破面、黑色孔洞——比此前任何版本都更糟糕。技术检查：223对自相交。

**根因**：Blender的`bridge_edge_loops`在两条边数差异较大（这里是20:50+）的环之间做自动配对时，采用的启发式算法容易产生扭曲、不均匀的长三角面，不适合这种量级的数量落差。

### 尝试4：手工按比例缝合（自己实现配对算法，替代Bridge） —— 反复调试仍未成功

**方法**：不依赖Bridge，自己实现"N对M环缝合"算法——把洞口边界按比例分配给干净环的每一段，手工生成三角/四边面。先后加入了：
1. 按连通关系走圈排序洞口顶点；
2. 检测并修正环与洞口的绕行方向（顺/逆时针）是否一致；
3. 放弃走圈排序、改为按绕轴角度重新排序洞口顶点（与干净环共用同一角度基准）。

**逐版结果**：
| 版本 | 非流形边 | 自相交对数 |
|---|---|---|
| 走圈排序，未修正绕向 | 0 | 390 |
| 走圈排序+绕向修正 | 0 | 326 |
| 改为按角度重排序 | **182**（新出现） | 650（更差） |

**根因（最终定位）**：躯干侧洞口边界紧邻手臂与浑圆躯干融合的过渡区，**这个边界形状在数学上不是一个能围绕手臂轴心简单参数化的规则环**（不是"从轴心看去角度单调递增"的星形凸包），而是一个不规则、局部凹陷的复杂曲线。按角度重排序会打乱洞口顶点真实的邻接关系，产生错误的三角配对（这解释了为什么这版反而出现了此前从未有过的非流形边）；按连通关系走圈排序虽然保住了真实邻接关系（0非流形），但"环小、洞大"这种量级悬殊的按比例扇形连接，在洞口形状不规则的情况下无法避免部分扇形三角互相折叠自相交。

**关键诊断数据**：对最后一版做了空间定位，182条非流形边里，躯干侧缝合区52条、手臂侧缝合区40条（左侧统计）——**说明连"更简单"的手臂侧连接，在改用角度排序后也被破坏了**，进一步证实"按角度排序"这个思路本身有问题，不只是躯干侧难。

## 二、根本性结论

这不是参数没调好，而是遇到了**真正的结构性难题**：把一个受控生成的、顶点数量少、间距均匀的干净圆环，无自相交地缝合到一个顶点数量多出2-3倍、形状不规则（尤其是躯干侧，因为手臂在这里已经融入浑圆的身体，不再是规则圆柱截面）的原生网格边界——这在计算几何上属于"不规则多边形边界的无自相交三角化/环间桥接"问题，专业做法通常需要人在建模过程中实时看着模型手动调整（判断哪几个点该连在一起、哪里该留三角过渡），而不是一次性用固定算法批处理生成。我作为脚本执行者没有这种"边看边调"的实时交互能力，只能"写脚本→整体跑一遍→事后看结果"，这个模式在处理这类需要局部视觉判断的不规则边界缝合问题时，反复验证下来是不可靠的。
