# 学生首页“今日学习”升级与任务聚合方案

> 本文是一份独立、可执行的产品与开发方案。目标是在保留现有学生首页、韩国语应用首页和各业务页面的前提下，把课程、作业、考试、章节巩固、专项训练、错题和老师推荐聚合成清晰的每日学习路线。本文是规划文档，不代表相关功能已经实现。

## 1. 关键决策

本方案已经明确以下信息架构原则：

- 不建立新的网络端口，系统继续使用现有服务端口。
- 不新增“今日学习”一级导航入口。
- 不新增与学生首页竞争的独立“今日学习中心”。
- 不把学生默认重定向到新的 `/today` 页面。
- 升级现有学生首页和现有韩国语应用首页。
- 现有课程、作业考试、巩固中心、专项训练和错题页面继续负责具体操作。
- 新建统一任务聚合服务，但不复制原业务数据。

最终结构：

```text
学生门户首页 /{space}
├── 跨应用今日摘要
├── 最重要的一项任务
├── 即将截止提醒
├── 最近反馈
└── 各应用入口

韩国语应用首页 /{space}/apps/korean
├── 韩国语今日必做
├── 继续上次学习
├── 今日建议
├── 本周学习计划
├── 最近成绩与反馈
└── 课程、作业、巩固、错题快捷入口

现有业务页面
├── 课程与教材
├── 作业与考试
├── 章节巩固
├── 专项训练
├── 错题复习
└── 成绩与学习记录
```

## 2. 背景

当前学生已经可以分别进入：

- 课程中心学习教材。
- 作业中心完成老师作业。
- 考试页面参加章节、阶段、期中和期末考试。
- 巩固中心进行章节巩固。
- 专项训练补强听、说、读、写、词汇和语法。
- 错题复习重新处理未掌握内容。
- 成绩页面查看分数和老师反馈。

现有功能较完整，但信息分散。学生登录后仍需要自己判断：

- 今天先做什么。
- 哪项任务最紧急。
- 上次学习停在哪里。
- 教材完成后应该做什么。
- 当前最薄弱的能力是什么。
- 哪些错题需要复习。
- 完成当前任务后下一步是什么。

因此，本项目不再增加新的业务中心，而是升级现有首页，让首页承担“组织已有功能”的职责。

## 3. 项目目标

### 3.1 学生目标

学生进入首页后，在几秒内回答：

1. 今天最重要的一项任务是什么。
2. 今天还有几项必做任务。
3. 哪项任务即将截止。
4. 上次学习到哪里。
5. 当前应该补强什么。
6. 完成以后下一步去哪。

### 3.2 教学目标

- 提高作业和考试按时完成率。
- 提高教材学习后的章节巩固率。
- 提高错题重新掌握率。
- 让专项训练真正服务于学生薄弱能力。
- 让老师能够设置学习目标并查看完成情况。
- 让机构负责人看到班级掉队和任务逾期情况。

### 3.3 技术目标

- 建立统一任务领域模型。
- 聚合现有业务状态，不修改原业务判定。
- 所有任务跳转到真实最终业务页面。
- 完成任务后及时刷新首页状态。
- 保留原有权限和多租户隔离。
- 不改变历史成绩、试卷快照和学习记录。

## 4. 非目标

本方案暂不包含：

- 新增独立“今日学习”页面。
- 新增“今日学习”一级导航。
- 修改作业、考试和巩固的判定规则。
- AI自动生成正式教学内容。
- AI口语自动评分。
- 短信、邮件、微信等外部通知渠道。
- 家长端学习报告。
- 商业套餐和付费功能。
- 立即扩展到所有语言和学科应用。

第一版先完整支持韩国语应用，同时让任务模型保留 `student_app_id`，为以后跨应用扩展做准备。

## 5. 两层首页职责

## 5.1 学生门户首页

现有路由：

```text
/{space}
```

现有职责包括：

- 学生身份和会员信息。
- 已开通应用入口。
- 最近课程和继续学习。
- 个人设置入口。

升级后继续作为全局门户，不变成韩国语专属页面。

建议新增的轻量内容：

- 跨应用最重要的一项任务。
- 今日剩余必做数量。
- 最近一项即将截止提醒。
- 最近一条老师新反馈。
- 进入对应应用的明确按钮。

门户首页只展示摘要，不展示完整任务列表。

示例：

```text
今天最重要
韩国语 · 第3章作业今天18:00截止
[继续完成]

今天还有2项必做 · 1条老师新反馈
```

### 5.1.1 门户首页不做什么

- 不展示几十张任务卡。
- 不复制韩国语完整学习计划。
- 不直接承载考试作答。
- 不直接承载章节巩固。
- 不替代各应用首页。

## 5.2 韩国语应用首页

现有路由：

```text
/{space}/apps/korean
```

现有页面复用学生学习首页能力。升级后，它是韩国语范围内的完整“今日学习”工作区。

建议结构：

```text
韩国语应用首页
├── 今天最重要
├── 今日必须完成
├── 继续上次学习
├── 今日建议
├── 本周学习计划
├── 最近成绩与老师反馈
└── 课程、作业、巩固、错题入口
```

韩国语应用首页展示详细任务，但具体作答和学习仍进入原页面。

## 5.3 现有业务页面

各页面继续负责：

| 页面 | 继续负责 |
|---|---|
| 课程与教材 | 内容学习、活动进度、课时完成 |
| 作业与考试 | 开始截止、草稿、提交、判分和批改 |
| 章节巩固 | 章节综合复习和掌握状态 |
| 专项训练 | 六项能力独立训练 |
| 错题复习 | 多来源错题和重新掌握 |
| 成绩与记录 | 成绩、评语和历史学习证据 |

首页只提供摘要、排序、推荐、状态和深链。

## 6. 角色与权限

## 6.1 平台负责人

可以：

- 配置任务类型默认优先级。
- 配置即将截止的时间范围。
- 配置系统建议数量上限。
- 配置薄弱项和错题推荐门槛。
- 查看跨机构使用趋势。

不能通过首页聚合功能直接修改学生成绩或历史提交。

## 6.2 机构负责人

可以：

- 查看本机构今日活跃率。
- 查看必做任务完成率。
- 查看逾期和长期未学习学生。
- 查看班级之间的差异。

不能修改平台标准课程、试卷和巩固内容。

## 6.3 老师

可以：

- 为负责班级设置本周学习目标。
- 推荐课程章节、章节巩固、专项训练和错题复习。
- 将推荐设置为必做或建议。
- 查看负责学生的今日完成情况。
- 查看未开始、进行中、逾期、待批改和已完成状态。

不能删除系统产生的作业、考试和截止提醒。

## 6.4 学生

可以：

- 查看自己的今日任务。
- 查看任务来源、截止时间和推荐原因。
- 进入真实业务页面完成任务。
- 设置个人周学习目标。
- 暂缓普通系统建议。
- 恢复被暂缓的建议。

不能：

- 隐藏老师必做任务。
- 隐藏考试截止提醒。
- 修改作业和考试时间。
- 查看其他学生任务。

## 7. 任务数据来源

第一版聚合以下来源：

| 任务类型 | 主要数据来源 | 默认性质 |
|---|---|---|
| 老师作业 | `learning_assignments`、目标关系、`learning_submissions` | 必做 |
| 正式考试 | `learning_assignments`中的考试类型及提交数据 | 必做 |
| 继续课程 | `lesson_progress`、`course_ebook_progress` | 系统建议 |
| 章节巩固 | `student_chapter_practice_progress` | 系统建议或老师推荐 |
| 专项训练 | `toolbox_practice_sessions`及能力数据 | 系统建议或老师推荐 |
| 错题复习 | `student_review_items` | 系统建议或老师推荐 |
| 老师推荐 | 新增老师推荐关系 | 老师决定 |
| 学生周计划 | 新增学生计划 | 学生自定 |

### 7.1 作业与考试

需要读取：

- 发布状态。
- 学生目标范围。
- 开始时间。
- 截止时间。
- 是否允许迟交。
- 最新草稿。
- 最新提交。
- 提交次数。
- 是否等待人工批改。
- 是否允许重交或补考。
- 成绩是否已经发布。

首页不能自行修改提交权限或判分状态。

### 7.2 继续课程

根据以下信息确定继续位置：

- 最近学习课程。
- 最近学习课时。
- 最近阅读教材章节。
- 最后有效活动位置。
- 当前进度。
- 章节是否已经完成。
- 下一章节是否开放。

“继续学习”必须进入最后有效位置，不能只跳到课程首页。

### 7.3 章节巩固

推荐条件：

- 教材完成但巩固未开始。
- 巩固已经开始但未完成。
- 巩固正确率低于掌握线。
- 老师指定重新巩固。
- 对应章节存在较多未掌握错题。

### 7.4 专项训练

推荐条件：

- 听、说、读、写、词汇或语法能力低于门槛。
- 最近有效练习数量不足。
- 某项能力连续在作业或考试中失分。
- 老师指定专项训练。

### 7.5 错题复习

推荐条件：

- 存在未复习错题。
- 同一知识点重复错误。
- 临近对应阶段考试。
- 老师要求复习。
- 已复习但尚未重新掌握。

## 8. 统一任务领域模型

首页不能直接消费多个数据表的原始字段。建议建立统一应用层类型：

```ts
type HomeLearningTask = {
  taskKey: string;
  studentAppId: string;
  appSlug: string;
  appLabel: string;
  sourceType:
    | "assignment"
    | "exam"
    | "course"
    | "chapter_practice"
    | "specialized_practice"
    | "review"
    | "teacher_recommendation"
    | "student_plan";
  sourceId: string;
  title: string;
  description: string | null;
  status:
    | "not_started"
    | "available"
    | "in_progress"
    | "submitted"
    | "pending_grading"
    | "completed"
    | "overdue"
    | "locked"
    | "unavailable";
  priority: "critical" | "high" | "normal" | "low";
  required: boolean;
  startsAt: string | null;
  dueAt: string | null;
  progressPercent: number | null;
  reason: string;
  href: string;
  courseId: string | null;
  courseChapterId: string | null;
  skill: string | null;
  updatedAt: string;
};
```

### 8.1 任务标识

```text
studentAppId:sourceType:sourceId
```

例如：

```text
korean-app-id:assignment:7f...
korean-app-id:chapter_practice:a2...
korean-app-id:review:grammar
```

### 8.2 聚合服务

建议代码位置：

```text
src/features/student-home-learning/
├── api/
│   ├── service.ts
│   └── types.ts
├── components/
│   ├── home-primary-task.tsx
│   ├── required-task-list.tsx
│   ├── continue-learning-card.tsx
│   ├── learning-recommendations.tsx
│   ├── weekly-learning-plan.tsx
│   └── recent-learning-feedback.tsx
├── priority.ts
├── recommendations.ts
├── routes.ts
└── status.ts
```

### 8.3 不复制来源数据

第一版通过服务器端聚合服务并行读取各来源，转换为统一任务模型。

只为以下新增业务建立新表：

- 老师推荐。
- 学生周计划。
- 普通建议的暂缓状态。

不建立作业、考试、课程和错题的任务副本总表。

## 9. 状态映射

## 9.1 作业和考试

```text
未到开始时间 → locked
已开放且无草稿 → available
存在草稿 → in_progress
已提交等待人工批改 → pending_grading
提交和批改流程结束 → completed
超过截止时间且未完成 → overdue
```

允许迟交时仍显示“已逾期”，同时提供“仍可提交”。

## 9.2 课程

```text
未开放 → locked
已开放未开始 → available
存在有效进度 → in_progress
课程或课时完成 → completed
```

## 9.3 章节巩固

```text
未发布 → unavailable
已发布未开始 → available
已开始未完成 → in_progress
完成但未达到掌握线 → in_progress，并显示“待加强”
达到掌握条件 → completed
```

## 9.4 错题复习

首页不按单题铺开。按课程章节或能力聚合，只显示主要复习任务，明细继续在错题中心展示。

## 10. 优先级与排序

第一版使用确定性规则，不使用不可解释的AI排序。

### 10.1 默认优先级

1. 已逾期但仍可完成的必做任务。
2. 今天截止的作业或考试。
3. 24小时内开始或截止的考试。
4. 老师标记为必做的推荐。
5. 明天截止的任务。
6. 已开始但未完成的课程或巩固。
7. 本周截止任务。
8. 错题复习。
9. 薄弱能力专项训练。
10. 普通继续学习建议。

### 10.2 同级排序

- 最早截止优先。
- 必做优先于建议。
- 已开始优先于未开始。
- 老师任务优先于系统建议。
- 最近更新优先。

### 10.3 门户首页选择规则

门户首页只取：

- 排序后的第一项作为“今天最重要”。
- 今日必做总数。
- 最近一项截止提醒。
- 最近一条已发布反馈。

不把完整任务数组传给门户首页组件。

### 10.4 去重规则

避免：

- 同一作业同时以作业和老师推荐出现。
- 同一章节同时显示多个相同继续入口。
- 已完成任务继续出现在今日必做。
- 未开放章节被推荐训练。
- 错题为零仍显示错题任务。
- 同一老师推荐与系统建议重复。

## 11. 学习推荐

### 11.1 推荐顺序

```text
有紧急必做任务
→ 先完成必做任务

无紧急任务但存在未完成课程
→ 继续上次课程

教材完成但章节未巩固
→ 完成章节巩固

巩固或考试暴露薄弱能力
→ 完成对应专项训练

存在未掌握错题
→ 进入错题复习

本章全部完成
→ 进入下一开放章节
```

### 11.2 推荐理由

每条系统建议必须说明具体原因，例如：

- “第3章教材已经完成，接下来完成章节巩固。”
- “语法最近正确率为58%，建议完成一次语法专项训练。”
- “有7道错题尚未重新掌握，建议集中复习。”
- “第4章上次学习到62%，可以从原位置继续。”

不显示内部规则编号、技术标签和装饰性英文类型名称。

### 11.3 建议暂缓

学生只可以暂缓普通系统建议：

- 今天稍后提醒。
- 明天提醒。
- 本周不再提示。

不能暂缓：

- 老师必做任务。
- 作业和考试截止提醒。
- 补考通知。

## 12. 学生门户首页改造

## 12.1 保留内容

保留：

- 顶部账户和机构信息。
- 已开通应用目录。
- 应用状态。
- 个人设置入口。
- 当前课程信息。

## 12.2 新增摘要模块

建议放置在问候区和应用目录之间：

```text
今天最重要
任务标题
来源应用 · 截止信息
推荐原因
[进入任务]
```

旁边或下方显示三个简洁数字：

- 今日剩余必做。
- 即将截止。
- 新反馈。

### 12.3 多应用规则

门户首页按照学生已开通应用聚合。

第一版只有韩国语数据时：

- 正常显示韩国语来源。
- 不显示空的英语、数学等任务区域。

以后其他应用接入后：

- 按统一优先级比较跨应用任务。
- 任务卡显示应用名称。
- 点击进入对应应用。

## 13. 韩国语应用首页改造

## 13.1 今天最重要

只显示一个主要任务，包含：

- 标题。
- 来源。
- 截止时间或当前进度。
- 为什么现在做。
- 唯一主要按钮。

## 13.2 今日必须完成

每张卡片显示：

- 任务标题。
- 作业、考试、补考或老师必做推荐。
- 开始或截止时间。
- 当前状态。
- 必做原因。
- 主要操作。

排序以紧急程度为主。

## 13.3 继续上次学习

只突出一个首要继续任务：

- 课程、课时和章节。
- 当前进度。
- 上次学习时间。
- 继续按钮。

其他课程放在现有课程入口中，不在首页堆叠多张大型卡片。

## 13.4 今日建议

最多展示3条：

- 建议内容。
- 推荐原因。
- 预计用时。
- 开始按钮。
- 可暂缓建议的次要操作。

## 13.5 本周学习计划

显示：

- 目标学习天数。
- 已完成天数。
- 本周学习时长。
- 已完成任务数。
- 剩余任务数。
- 连续学习天数。
- 本周目标完成率。

## 14. 交互与视觉要求

- 每个区域只有一个主要操作。
- 任务卡可以整卡点击，但不能嵌套冲突链接。
- 核心触控区域至少44px。

- 完成任务返回后刷新任务、数量和建议。

```text
src/features/student-home-learning/routes.ts
```

需要覆盖：

- 考试详情。
- 课程最后学习位置。
- 章节巩固详情。
- 指定能力和章节的专项训练。
- 错题复习及来源题目。
- 成绩和老师评语。

无法生成具体深链时，安全回退到对应模块目录，不生成404链接。
