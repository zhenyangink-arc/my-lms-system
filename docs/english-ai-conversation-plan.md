# 英语 AI 自由对话：实施方案

> 决定（2026-10-01）：英语先做 **AI 自由对话**，复用韩语“AI 交流体验”的功能结构，换成英语口语陪练提示词，按大学英语水平；回答模式沿用三种；使用权限与韩语相同（vip2 / vip3）。情景会话练习待有英语场景内容后再做；写作批改以后结合四六级备考单独考虑。

## 1. 韩语现状

| 部分 | 位置 | 说明 |
|---|---|---|
| 入口与页面 | `src/app/dashboard/conversation-practice/ai-experience/**`（已按应用传参） | 入口页提供“快速体验”和“正式练习（选择情境）”两种方式 |
| 对话组件 | `ConversationAiExperience.tsx`（约 1000 行，客户端） | 约 10 处界面文字写死“韩语”，回答模式按钮为“智能跟随 / 韩语沉浸 / 初级辅助” |
| 文字对话 | `src/app/api/conversation-practice/ai-experience/qwen-chat/route.ts`（黄区）→ 数据库平台函数 `supabase/functions/qwen-conversation-chat` | 函数中的系统提示词写死“韩语口语陪练老师” |
| 语音对话 | `api/.../chat`、`api/.../ws-ticket`（黄区）→ 外部会话服务（`CONVERSATION_AI_BASE_URL` / `CONVERSATION_AI_WS_URL`） | 语音识别与朗读由外部服务完成，不在本仓库 |
| 每日次数限制 | 上述接口中的 `CONVERSATION_AI_DAILY_MESSAGE_LIMIT` | 按学生计数，不分学科 |

## 2. 需要的改动

1. **学科清单**：英语学生导航加入“会话练习”入口；新增清单字段声明会话能力（例如“自由对话：开；情景练习：关”），英语入口页只显示“快速体验”。
2. **路由**：新增 `/[space]/apps/english/conversation-practice/ai-experience`（及 `quick`），复用现有页面，传入 `"english"`。
3. **对话组件**：把写死的“韩语”文字与回答模式标签改为按学科取值（英语：智能跟随 / 英语沉浸 / 中英辅助）；组件请求接口时带上学科。
4. **接口（黄区，Codex 收尾后）**：接收学科参数；学科由客户端传入，必须在服务端核对该学生对此应用的有效开通（与练习计时器相同的做法），再转发给 AI 函数。
5. **AI 函数**：按学科选择系统提示词与回答模式说明（见第 3 节初稿），未传学科时保持韩语，避免影响现有调用。
6. **语音模式**：外部会话服务需支持英语语音识别与朗读。在此之前，英语只开放文字对话，隐藏语音切换。
7. **每日次数**：建议各学科共用同一个每日上限（与现在一致），不单独计数。
8. **验证**：真实 AI 回复需要在配置了 AI 服务密钥的环境中验证；本机隔离验证库没有这些配置，只能验证页面、权限与请求内容。

## 3. 英语陪练提示词初稿（待确认）

```text
你是一位专业、耐心的英语口语陪练老师，面向中国大学生，帮助他们提高英语口语表达和日常、校园、学术场景下的交流能力。

回答规则：
- 用户主要用中文提问时，只用中文回复；不要夹带英语、括号翻译或双语对照。
- 用户主要用英语提问时，只用英语回复；不要夹带中文、括号翻译或双语对照。
- 用词和句子难度以大学英语四、六级水平为准，自然口语化，避免过于生僻的表达。

身份说明：你是本平台的 AI 英语口语陪练，帮助学生进行英语表达和情景对话练习。用户询问“你是什么模型”“谁开发的”等身份或技术实现问题时，只说明上述产品身份，不透露、猜测或确认底层模型、供应商或技术架构。可简短回答：“我是本平台的 AI 英语口语陪练，专注陪你练习英语表达和日常对话。”

保持自然、简洁。只有当用户使用英语且存在明显的语法、用词或表达问题时，才用英语简要纠正，给出更自然的说法，并接一小段可以继续对话的回复。
```

回答模式说明（附加在系统提示词后）：

| 模式 | 说明 |
|---|---|
| 智能跟随 | 中文输入用中文回答，英语输入用英语回答 |
| 英语沉浸 | 用户输入英语时，必须只用英语回答 |
| 中英辅助 | 用户输入英语时，以英语回答，并在每个关键句后附简短中文释义；用户输入中文时只用中文回答 |
