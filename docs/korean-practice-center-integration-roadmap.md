# 韩国语巩固中心管理端与学生端贯通方案

> 本文整理自对韩国语学生端“巩固中心”的代码与数据库检查。用于明确现状、问题、目标、数据关系、功能范围、实施顺序和验收标准。本文是规划文档，不代表相关改造已经完成。

## 1. 背景

目标页面：

- 学生端：`/[space]/apps/korean/practice/course`
- 当前示例地址：`/yuanzhi/apps/korean/practice/course`

用户反馈：

- 巩固中心与管理端的连接可能存在问题。
- 希望继续完善项目，而不是只做验证。

本次检查沿着以下链路进行：

```text
管理端课程与教材配置
→ 数据库内容及发布状态
→ 学生端课程巩固目录
→ 章节巩固内容
→ 学生进度
→ 错题与复习
→ 管理端学情数据
```

## 2. 核心结论

当前并非某个接口或按钮单独失效，而是“课程巩固”仍使用一套旧的、局部写死的数据结构，没有真正接入现有的课程管理、互动教材、练习工具、作业考试和学习记录体系。

当前三个板块的实际情况：

| 板块 | 当前状态 | 主要问题 |
|---|---|---|
| 课程巩固 | 连接不完整 | 使用旧章节测试目录、硬编码精研内容和浏览器本地进度 |
| 专项训练 | 基本连接 | 已读取练习工具和六项练习数据，仍需与统一进度体系对接 |
| 错题复习 | 部分连接 | 只读取旧章节小测中学生主动收藏的题目 |

下一项推荐任务：

> 重构韩国语巩固中心的数据闭环：增加管理端“巩固中心管理”，让学生端课程巩固读取真实课程章节与已发布内容，将精研进度保存到数据库，并统一作业、考试和专项训练错题。

## 3. 当前已连接的部分

### 3.1 韩国语应用授权

学生进入韩国语应用前，系统已经检查：

- 当前机构是否启用韩国语应用。
- 学生是否被机构开通韩国语应用。
- 授权是否处于有效时间范围内。

这部分属于应用级授权，能够阻止未授权学生通过手动输入地址进入韩国语应用。

### 3.2 专项训练数据

管理端“练习工具”当前可以管理或展示：

- 六项练习入口。
- 工具启用状态和展示顺序。
- 关联课程。
- 词汇库。
- 语法库。
- 语法例句和音频字段。

当前数据库检查结果：

| 数据 | 数量 |
|---|---:|
| 已发布韩国语课程 | 5 门 |
| 已发布课程章节 | 34 章 |
| 已发布专项练习 | 200 个 |
| 具备六项专项练习的实际教学章节 | 33 章 |

“课程总览”不需要六项专项练习，所以33个实际教学章节的覆盖关系基本完整。

## 4. 当前主要问题

## 4.1 课程目录没有读取真实课程结构

学生端课程巩固目前直接读取 `chapter_tests`，并将课程范围固定为：

```text
hangul-introduction
korean-level-one
```

但管理端的真实课程结构是：

```text
courses
→ lessons
→ course_chapters
```

由此造成：

- 管理端新增或发布其他韩国语课程后，不会自动出现在课程巩固。
- 韩国语中级、高级、生活韩语、TOPIK等课程无法进入课程巩固目录。
- 章节测试被错误地承担了课程目录职责。
- 没有关联章节测试的已发布课程章节不会显示。
- 管理端课程锁定、开放时间和前置章节规则无法完整生效。

当前数据差异：

| 数据来源 | 数量 |
|---|---:|
| 管理端已发布课程 | 5 门 |
| 管理端已发布章节 | 34 章 |
| 课程巩固读取的章节测试 | 20 个 |
| 课程巩固硬编码课程 | 2 个 |

## 4.2 每章精研内容为前端硬编码

当前所有章节都会进入同一套韩文字母精研工作台，主要内容包括：

- 가、고、한、읽等固定音节。
- 初声、中声、终声。
- 拼装、拆解、纠错和分类。
- 固定的案例、比较和总结。

当前结果：

- 字母入门章节使用这套内容基本合理。
- 韩国语一级第1—16章仍然显示同一套字母拼装内容。
- 其他课程如果接入后也会重复显示这套内容。
- 页面标题会变化，但正文内容不会随章节变化。
- 管理端修改教材词汇、语法、课文或练习，精研工作台不会同步变化。

## 4.3 精研进度只保存在浏览器

“本章掌握”目前保存在浏览器 `localStorage`，未写入数据库。

由此造成：

- 换设备后进度消失。
- 清理浏览器缓存后进度消失。
- 手机与电脑进度不一致。
- 老师无法查看。
- 机构负责人无法统计。
- 平台无法分析。
- 学情中心无法引用。
- 结课认证无法使用。

浏览器本地存储可以作为断网临时缓存，但不能作为最终学习记录。

## 4.4 多套进度口径互不一致

当前存在至少三种进度：

```text
电子书阅读进度
章节测试通过进度
本地精研互动进度
```

具体表现：

- 目录中的“知识精研总进度”实际根据章节测试通过数量计算。
- 章节卡片同时混合电子书进度和章节测试成绩。
- 详情页“本章掌握”根据本地互动完成数量计算。
- 详情页达到100%后，目录不一定同步。
- 管理端完全看不到本地精研进度。

需要统一“学习、练习、测试、掌握”的状态定义，避免将不同指标都称为“精研进度”。

## 4.5 管理端缺少课程巩固内容管理

当前管理端“练习工具”主要管理：

- 工具入口。
- 词汇库。
- 语法库。

管理端还不能管理：

- 每章课程巩固内容。
- 每章快速回顾。
- 每章精讲。
- 每章易混对比。
- 每章互动任务。
- 每章巩固完成条件。
- 草稿、预览和发布状态。
- 学生端展示顺序。
- 巩固内容覆盖率。

因此当前学生端课程巩固没有可靠的管理端内容来源。

## 4.6 听音训练仍为空壳

听音训练目前可以展示章节目录，但进入章节后只显示占位提示。

现有数据库已经具备：

- 听力专项练习。
- 部分听力文本。
- 教材和作业中的听力来源。

课程巩固尚未读取这些数据。

## 4.7 错题复习只连接旧章节小测

当前错题复习只读取学生在旧章节测试中主动点击“加入复习”的题目。

尚未自动归集：

- 老师作业错题。
- 正式章节考试错题。
- 阶段考试错题。
- 期中和期末考试错题。
- 专项训练错题。
- 补考仍然错误的题目。
- 口语和写作的老师改进建议。

因此当前功能更接近“收藏的章节小测题”，还不是统一错题中心。

## 4.8 发布后的刷新链路不完整

平台负责人发布教材章节后，目前会刷新教材、章节测试、作业和学生教材页面，但没有同步刷新课程巩固页面。

后续课程巩固接入教材后，发布动作必须同时更新巩固内容状态并刷新相关学生页面。

## 4.9 页面体验问题

- 窄屏下多个固定宽度统计卡容易拥挤。
- 大量状态文字使用8—10像素字号，可读性偏低。
- 课程默认全部折叠，学生进入后不容易快速找到当前任务。
- “继续精研”只参考电子书和章节测试，没有参考作业、错题和近期学习。
- 锁定章节只显示“完成上一章测试”，没有显示具体还差什么。
- 课程巩固、专项训练和错题复习之间的数据关系没有体现。
- 空状态和错误状态缺少针对性的恢复操作。

## 5. 产品定位

三个板块应承担不同职责：

| 板块 | 产品定位 |
|---|---|
| 课程巩固 | 围绕某一课程章节，把教材、词汇、语法、听说读写、作业和测试串成综合复习路线 |
| 专项训练 | 跨课程集中训练听、说、读、写、词汇、语法中的某一项能力 |
| 错题复习 | 汇总所有学习、作业、考试和专项训练中的错误及老师改进建议 |

课程巩固不再是一套独立写死的韩文字母互动页面，而应成为按章组织的综合巩固入口。

## 6. 目标业务流程

```text
平台负责人维护课程、教材和练习
→ 发布课程章节
→ 系统检查该章内容来源
→ 自动生成章节巩固包草稿
→ 平台负责人预览并发布
→ 机构已开通韩国语应用的学生可见
→ 学生完成回顾、练习和检测
→ 进度与结果写入数据库
→ 错题进入统一复习池
→ 老师、机构和平台查看巩固数据
```

## 7. 管理端“巩固中心管理”

建议在韩国语管理端新增独立模块“巩固中心管理”。

### 7.1 章节巩固覆盖矩阵

按真实课程树展示：

```text
课程
→ 课时
→ 章节
→ 巩固内容
```

每章显示：

- 课程和章节发布状态。
- 教材是否发布。
- 核心词汇数量。
- 核心语法数量。
- 听、说、读、写、词汇、语法六项练习是否齐全。
- 作业是否发布。
- 章节测试是否发布。
- 巩固内容是否生成。
- 巩固内容版本。
- 巩固内容状态。
- 上次同步时间。
- 是否因来源变化需要更新。

建议状态：

```text
未生成
草稿
待检查
已发布
需更新
已停用
```

### 7.2 自动生成章节巩固包

平台负责人发布教材章节后，系统可以从已有权威数据生成：

- 本章快速回顾。
- 核心词汇复习。
- 核心语法复习。
- 易混内容对比。
- 听力练习。
- 口语练习。
- 阅读练习。
- 写作练习。
- 本章错题入口。
- 自我检测。

生成后默认保持草稿，不自动向学生发布。

### 7.3 内容编辑与预览

平台负责人可以：

- 调整内容块顺序。
- 启用或停用某个内容块。
- 修改标题和操作说明。
- 选择内容来源。
- 调整完成条件。
- 查看数据缺失提示。
- 预览桌面端和手机端效果。
- 发布新版本。

不建议让前端根据活动类型自动生成装饰性标签；只保留对学习有直接帮助的自然语言标题和提示。

### 7.4 学生练习数据

管理端可以查看：

- 已开放学生人数。
- 开始巩固人数。
- 完成人数。
- 完成率。
- 平均掌握度。
- 平均练习次数。
- 高频错词。
- 高频错语法。
- 六项薄弱分布。
- 长期无人使用的章节。
- 内容异常或大量答错的练习。

## 8. 学生端课程巩固

## 8.1 课程巩固首页

首页优先展示：

1. 继续巩固。
2. 当前课程和当前章节。
3. 本章尚未完成的巩固项目。
4. 最近错题和薄弱能力。
5. 已报名或已开放课程目录。

课程与章节必须来自真实课程结构，不再根据章节测试拼接。

### 8.2 章节状态

建议统一为：

```text
未开始
巩固中
待加强
已掌握
未开放
内容准备中
```

状态不能只依赖颜色，还应提供图标和文字说明。

### 8.3 章节巩固详情

建议按以下顺序组织：

```text
本章回顾
→ 核心词汇
→ 核心语法
→ 易混对比
→ 听说读写综合练习
→ 本章错题
→ 自我检测
→ 巩固结果
```

不是每一章都必须机械显示完全相同的组件；系统应根据本章实际内容生成。

### 8.4 字母章节兼容

现有韩文字母拼装、拆解、纠错和分类互动可以保留，但只应用于适合的字母和发音章节。

其他章节必须读取自身内容，不能继续复用同一组가、고、한、읽案例。

### 8.5 听音训练

听音训练应读取真实数据，包括：

- 本章听力材料。
- 可重复播放的音频。
- 听前目标。
- 听辨题。
- 听后反馈。
- 播放次数。
- 学生正确率。

正式音频尚未提供时，应明确标识临时语音状态，避免误认为正式录音。

## 9. 统一学习进度

## 9.1 进度定义

需要区分：

| 指标 | 含义 |
|---|---|
| 教材进度 | 学生阅读和完成教材活动的程度 |
| 巩固进度 | 学生完成本章巩固内容块的程度 |
| 练习正确率 | 学生在巩固练习中的作答表现 |
| 测试成绩 | 章节小测、作业或正式考试成绩 |
| 掌握状态 | 综合教材、练习、测试和错题得出的结果 |

不能再将章节测试通过率直接命名为“精研进度”。

## 9.2 建议掌握规则

示例规则：

- 巩固内容完成率达到100%。
- 巩固练习正确率达到80%。
- 本章关键错题已完成复习。
- 章节测试达到平台规定分数。

最终规则由平台负责人配置，学生页面显示明确条件。

## 9.3 数据保存

数据库作为最终来源，保存：

- 学生。
- 机构。
- 课程章节。
- 巩固包及版本。
- 已完成内容块。
- 当前学习位置。
- 练习正确率。
- 开始时间。
- 最后学习时间。
- 完成时间。
- 掌握状态。
- 薄弱能力。

浏览器本地存储仅用于临时缓存和断线恢复。

## 10. 统一错题中心

统一错题来源：

- 章节小测。
- 老师作业。
- 正式章节考试。
- 阶段考试。
- 期中考试。
- 期末考试。
- 专项训练。
- 巩固自测。
- 补考。
- 学生主动收藏。
- 口语和写作的老师建议。

每个复习项目保存：

- 来源类型。
- 来源任务和试卷版本。
- 原题快照。
- 学生原答案。
- 正确答案或评分建议。
- 所属课程和章节。
- 所属能力。
- 错误次数。
- 最近错误时间。
- 最近复习时间。
- 是否重新掌握。

口语和写作不使用简单“正确/错误”，而应展示评分标准、老师评语和改进任务。

## 11. 建议数据模型

以下名称为建议，实施前可根据现有数据库命名规范调整。

### 11.1 章节巩固包

建议表：`chapter_practice_units`

主要字段：

- `id`
- `student_app_id`
- `course_chapter_id`
- `source_textbook_chapter_id`
- `version`
- `status`
- `title`
- `completion_rule`
- `source_snapshot`

- 学生只能读取已发布版本。

## 12. 发布与同步规则

### 12.1 教材发布

发布教材章节时：

1. 检查关联课程章节。
2. 检查章节测试和专项练习来源。
3. 如果尚无巩固包，则生成草稿。
4. 如果已有已发布巩固包且来源发生变化，则标记为“需更新”。
5. 刷新管理端巩固覆盖矩阵。
6. 刷新学生端课程巩固目录。

不建议修改教材后直接改变学生正在使用的已发布巩固版本。

### 12.2 巩固包发布

发布前检查：

- 对应课程章节存在且已发布。
- 标题和操作说明完整。
- 必需内容块存在。
- 所有客观练习具有判定配置。
- 内容来源仍然有效。
- 完成规则有效。
- 听力内容明确音频状态。
- 无重复排序和无效引用。

### 12.3 版本规则

```text
草稿
→ 待检查
→ 已发布
→ 来源发生变化
→ 需更新
→ 创建新版本
→ 旧版本保留历史学习记录
```

## 13. 权限建议

### 平台负责人

- 生成、编辑、预览和发布标准巩固包。
- 管理完成规则。
- 查看所有机构使用数据。
- 创建新版本。
- 停用存在严重问题的内容。

### 机构负责人

- 查看平台已发布巩固内容。
- 查看本机构使用情况。
- 查看完成率和薄弱项。
- 不能修改平台标准内容和答案。

### 老师

- 查看负责学生的巩固进度。
- 查看班级薄弱章节和错题。
- 向学生推荐某章或某项训练。
- 不能修改平台标准内容。

### 学生

- 读取本机构已开放应用中的已发布内容。
- 保存自己的进度和答案。
- 查看自己的错题、建议和掌握状态。
- 不能访问草稿或其他学生数据。

## 14. 实施顺序

## 第一轮：打通课程与管理端数据

目标：让课程巩固目录读取真实课程结构。

任务：

- 使用 `courses → lessons → course_chapters` 生成目录。
- 移除两个固定课程键的限制。
- 接入课程、课时和章节发布状态。
- 接入开放时间、手动锁定和前置关系。
- 建立章节巩固包数据表。
- 增加管理端巩固覆盖矩阵。
- 补齐教材发布后的同步与刷新。

完成标志：

- 管理端发布符合条件的新课程后，可以进入巩固覆盖矩阵。
- 发布巩固包后，学生端能够看到对应课程和章节。
- 草稿内容不会被学生读取。

## 第二轮：重做章节巩固详情

目标：每章展示自己的真实内容。

任务：

- 保留字母章节现有互动能力。
- 将硬编码字母内容限制在适合的章节。
- 韩国语一级各章读取自己的词汇、语法和六项练习。
- 其他课程读取各自课程章节内容。
- 建立快速回顾、重点练习、自我检测和结果页。
- 听音训练接入真实听力数据。

完成标志：

- 不同章节显示不同内容。
- 管理端内容更新后能够生成新版本。
- 学生作答具有明确反馈和下一步操作。

## 第三轮：统一进度与错题

目标：让巩固数据进入教学闭环。

任务：

- 精研进度写入数据库。
- 支持刷新、换设备和断线恢复。
- 统一电子书、巩固、练习和测试状态。
- 自动归集作业、考试、专项训练和巩固错题。
- 老师查看负责学生的巩固进度和薄弱项。
- 根据真实薄弱项生成下一步建议。

完成标志：

- 同一学生在不同设备上进度一致。
- 老师能够查看学生巩固记录。
- 错题中心能够显示多个来源的复习项目。

## 第四轮：界面与体验优化

目标：让学生快速理解当前任务并顺利完成。

任务：

- 首页优先展示“继续巩固”。
- 自动展开当前课程。
- 统一章节状态。
- 手机端统计区域可换行。
- 提高正文和状态文字可读性。
- 锁定状态显示具体开放条件。
- 空状态提供返回课程、刷新或开始学习操作。
- 课程巩固、专项训练和错题复习形成互相跳转。

完成标志：

- 小屏无横向滚动。
- 核心操作触控区域足够大。
- 状态不只依靠颜色表达。
- 学生进入页面后可以快速找到下一项任务。

## 15. 数据迁移与兼容

### 15.1 现有章节测试

- 保留现有 `chapter_tests` 和历史作答。
- 不再将其作为课程目录来源。
- 继续作为章节小测或章节测试来源。

### 15.2 现有本地精研进度

- 首次上线数据库进度后，可以尝试读取本地缓存。
- 若数据库暂无记录，可询问学生是否导入本机进度。
- 导入后以数据库为准。
- 本地数据不可直接覆盖较新的服务器进度。

### 15.3 现有错题收藏

- 将旧 `chapter_test_question_reviews` 映射到统一复习项目。
- 保留原表或建立兼容视图。
- 历史收藏时间和题目关系不能丢失。

### 15.4 现有专项训练

- 继续使用现有200个已发布练习。
- 章节巩固包只引用或快照相关练习，不复制出无管理关系的重复题库。
- 专项训练记录继续独立统计，同时可以为巩固推荐提供证据。

## 16. 验收标准

### 管理端连接

- [ ] 课程巩固读取真实课程、课时和章节结构。
- [ ] 不再硬编码两个课程。
- [ ] 平台负责人能够查看所有章节巩固覆盖状态。
- [ ] 平台负责人可以生成、预览和发布巩固包。
- [ ] 机构和老师只能看到已发布内容。
- [ ] 教材来源变化后能够提示巩固内容需更新。

### 学生端内容

- [ ] 不同章节显示不同巩固内容。
- [ ] 字母互动仅用于适合的章节。
- [ ] 词汇、语法和六项练习来自已发布权威数据。
- [ ] 听音训练不再是占位页面。
- [ ] 学生能够看到明确的完成条件和下一步操作。

### 进度

- [ ] 精研进度写入数据库。
- [ ] 刷新页面后进度不丢失。
- [ ] 换设备后进度一致。
- [ ] 目录和详情使用一致口径。
- [ ] 老师和机构可以读取授权范围内的进度。

### 错题复习

- [ ] 旧章节小测收藏得到保留。
- [ ] 作业、正式考试和专项训练错题能够自动归集。
- [ ] 口语和写作能够保存老师改进建议。
- [ ] 复习后能够标记重新掌握。

### 权限与历史数据

- [ ] 学生不能读取草稿。
- [ ] 学生不能读取其他学生进度。
- [ ] 机构之间数据隔离。
- [ ] 已发布内容通过新版本更新。
- [ ] 新版本不会改变历史练习结果。

### 体验

- [ ] 手机端无横向滚动和统计卡拥挤。
- [ ] 正文和状态文字具备可读字号与对比度。
- [ ] 锁定、错误和空状态都有明确恢复路径。
- [ ] 当前章节和下一项任务清晰可见。

## 17. 本方案暂不包含

- 删除现有章节测试、专项训练或历史进度数据。
